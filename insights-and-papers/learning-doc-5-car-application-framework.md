# 学习文档 5：CAR 应用框架

> 本文档对应学习路线第五层。将前四层学到的因果抽象理论映射到 CAR agent 安全系统的具体场景中。
>
> **前四层核心回顾**:
> - 文档 1 (因果抽象): 如何验证神经网络实现了高层因果模型（交换干预 + IIA）
> - 文档 2 (DAS): 如何处理分布式表征（旋转矩阵 + 子空间对齐）
> - 文档 3 (非线性困境): 为什么线性约束是必需的（否则因果解释空洞）
> - 文档 4 (LRH): 线性表征的形成条件和限制（频率阈值 + 多维表征）

## 一、CAR 的高层因果模型定义

### 1.1 为什么要定义高层因果模型

因果抽象的起点永远是**高层模型 H**——那个人类可理解的、我们希望 N 去"实现"的因果结构。在 IOI 任务中，H 是"主语是谁"的计算图。在 CAR 中，H 应该刻画"工具调用如何因果地改变系统状态"。

### 1.2 因果变量

CAR 的高层因果变量是**因果效果集合**：

$$\mathcal{V}_{\text{CAR}} = \{
\text{command\_executed},
\text{file\_written},
\text{file\_deleted},
\text{file\_content\_read},
\text{message\_sent},
\text{network\_egress},
\text{subagent\_spawned},
\text{memory\_updated},
\text{tool\_error},
\text{noop},
\text{...}\}$$

每个变量是**二元的**（发生了 / 没发生），且变量之间存在因果关系：
- `command_executed` 可能引起 `tool_error`（如果命令失败）
- `file_written` 可能引起 `state_changed`（文件系统状态改变）
- `network_egress` 可能引起 `message_sent`（网络出站 → 外部消息发送）

### 1.3 因果图

CAR 的效果之间不是独立的，它们构成一个因果图：

```
tool_name ──→ command_executed ──→ network_egress
     │              │
     │              └──→ file_written ──→ state_changed
     │              │
     │              └──→ tool_error
     │
     └──→ file_content_read (直接效果, 无下游)
     │
     └──→ subagent_spawned ──→ command_executed (递归)
```

这个图的关键性质：
1. **工具名是根节点**——它因果地决定了哪些效果可能发生
2. **效果间有因果依赖**——如 `command_executed → network_egress`（网络命令需要 shell 执行）
3. **状态上下文是混杂因子** —— `safe_mode` 同时影响工具选择和效果结果

### 1.4 干预操作

在 CAR 的高层因果模型中，干预定义如下：

**do(tool = T)**: 强制调用工具 T，无论当前状态如何。

这对应于 Pearl 因果之梯的第二层——我们从"观测到用户调用了 terminal"（P(effect | observe terminal)）上升到"如果我们强制调用 terminal"（P(effect | do(terminal))）。

**do(effect = 1)**: 强制某个效果发生，无论工具如何。

这在 CAR 的安全分析中很重要——"如果我们强制产生 `command_executed` 这个效果，其他的效果会受到影响吗？" 这是反事实推理的起点。

## 二、CAR 的低层表征来源

### 2.1 可用的表征源

CAR 可以从多个来源提取低层激活：

| 来源 | 维度 | 内容 | 获取方式 |
|------|------|------|---------|
| **LLM 最后层隐藏状态** | 4096+ (取决于模型) | 工具调用上下文的完整语义编码 | LLM API (如 OpenAI embeddings) |
| **LLM 中间层隐藏状态** | ~4096 × N_layers | 不同抽象级别的语义信息 | 需要模型支持（开源模型） |
| **CAR 状态编码器** (如果实现) | ~128-256 | 状态模式 + 工具类型的联合编码 | 自定义编码器 |
| **SAE 特征** (如果训练) | ~数万 | 从 LLM 激活中分解的稀疏可解释特征 | 需要训练 SAE |

### 2.2 初始阶段的实用选择

考虑到 CAR 目前没有部署、没有训练数据、没有自定义编码器，**最实际的起点是用 LLM 的冻结嵌入作为低层表征**。

**理由**:
1. Do-PFN (2025) 已经证明预训练模型的冻结 embedding 包含因果信号
2. 不需要训练额外的编码器
3. LLM embedding 可以在离线阶段预计算和缓存
4. 如果 API 模型不支持中间层访问，可以用文本嵌入 API 作为替代

### 2.3 需要的表征预处理

在应用 DAS 之前，需要对 LLM embedding 做基本预处理：

1. **降维** (如果维度太高): PCA 到 256-512 维，同时保留方差的 95%+
2. **标准化**: 每个维度减去均值除以标准差
3. **正交化** (可选): 使各维度线性独立（有助于 DAS 的旋转矩阵初始化）

## 三、实验设计

### 3.1 总览

CAR 的因果可解释性研究由五个实验组成：

```
实验 1: 线性可编码性扫描   → 哪些因果效果被线性编码？
实验 2: DAS 对齐搜索       → 能否找到因果效果的线性子空间？
实验 3: 线性 vs 非线性对比  → 线性 τ 的 IIA 能接近非线性 τ 吗？
实验 4: 交换干预验证       → 找到的对齐是否真正是因果的？
实验 5: 频率梯度分析       → 线性编码质量与执行频率的关系
```

### 3.2 实验 1: 线性可编码性扫描

**目标**: 筛查哪些因果效果在 CAR 的表征空间中被线性编码。

**方法**:
1. 收集 CAR 的执行数据: 每个工具调用采集 `(状态, 工具, LLM_embedding, 实际效果)`
2. 对每个因果效果 $E_i$:
   - 训练线性探针: $\hat{E}_i = \sigma(W_i^T h + b_i)$，其中 $W_i$ 是探针权重，$h$ 是 LLM 嵌入
   - 记录 R²（连续）或 F1（二元）
3. 按 R²/F1 排序所有效果

**预期输出**: 一个"线性可编码性排行榜"——哪些效果容易被线性读出，哪些困难。

**解读**:
- 高 R² 的效果（如 file_written, command_executed）：天然线性编码，适合用 DAS 做因果对齐
- 低 R² 的效果（如 webhook_registered, authentication_bypassed）：非线性编码或在当前表征中不可编码
- **关键测量**: 线性可编码的效果比例——这将决定"线性约束的因果抽象在 CAR 中能覆盖多少安全关键效果"

### 3.3 实验 2: DAS 对齐搜索

**目标**: 在 CAR 的表征空间中找到与因果效果对应的线性子空间。

**方法**:
1. 选择实验 1 中线性可编码性最高的 3-5 个效果作为目标
2. 构建 CAR 的高层因果模型 H（如 §1.2 所定义）
3. 使用 DAS:
   - 初始化正交旋转矩阵 R
   - 为每个目标效果分配子空间（初始维度: 5-20，基于实验 1 的 R² 估计最优维度）
   - 训练 R 和子空间划分（如果用边界 DAS）以最大化交换干预准确率
4. 记录最终 IIA 和子空间维度

**预期输出**: 每个效果的因果子空间（旋转后的维度索引）和对应的 IIA。

**关键挑战**: CAR 没有"基准输入"和"源输入"的自然区分——每次工具调用是一个独立的事件。需要设计"伪交换干预":
- **基准**: 一次产生效果 E 的工具调用
- **源**: 一次不产生效果 E 的工具调用（在其他状态维度尽可能相似）
- **伪交换**: 将基准激活中"E 的子空间"替换为源激活中对应的子空间

### 3.4 实验 3: 线性 vs 非线性对比

**目标**: 验证 Sutter et al. 非线性困境在 CAR 中的具体表现。

**方法**:
1. 对每个目标效果，训练两个版本的对齐映射:
   - **线性 τ**: $τ_L(h) = W h + b$（单层线性 + sigmoid）
   - **非线性 τ**: $τ_{NL}(h) = \text{MLP}(h)$（3 层，隐藏维度 256，ReLU 激活）
2. 在相同的交换干预任务上比较两者的 IIA
3. 计算 $\Delta = \text{IIA}_{NL} - \text{IIA}_L$

**预期与解读**:

| 场景 | Δ 值 | 解读 |
|------|------|------|
| Δ ≈ 0 | 线性 τ 匹敌非线性 τ | 该效果被线性编码，因果解释可靠 |
| Δ 中等 (0.1-0.2) | 非线性 τ 略优 | 部分信息是非线性编码的 |
| Δ 很大 (>0.3) | 非线性 τ 显著优于线性 τ | 该效果主要被非线性编码，线性解释不够 |
| IIA_L 低 + IIA_NL 低 | 两者都失败 | 该效果在当前表征中根本不可恢复 |

**关键推论**: 如果大部分安全关键效果（如 `command_executed`, `file_deleted`, `network_egress`）的 Δ 接近于 0，那么线性约束的因果抽象在 CAR 中是充分的——这是一个可发表的基础发现。

### 3.5 实验 4: 交换干预验证

**目标**: 验证 DAS 找到的对齐是否真正是因果的（而不仅仅是统计相关的）。

**方法**:
1. 使用实验 2 找到的子空间和旋转矩阵 R
2. 在**未见过的**工具调用数据上做交换干预:
   - 选择"关键效果"作为干预目标
   - 基准调用和源调用在"该效果是否发生"上有不同
   - 交换该效果对应的子空间
3. 验证:
   - **忠实性**: 交换后的效果预测是否按因果模型预期变化？
   - **特异性**: 交换其他效果的子空间是否**不**改变目标效果的预测？

**预期输出**: 忠实性和特异性的量化指标——这是因果对齐质量的严格度量。

**为什么这比实验 2 的二分类更强**: 实验 2 只是说"交换后效果预测变了"。实验 4 说"交换后效果预测按照**因果模型预测的精确方式**变了"。前者是关联，后者是因果。

### 3.6 实验 5: 频率梯度分析

**目标**: 验证 LRH 的频率阈值在 CAR 的因果效果中是否成立。

**方法**:
1. 按执行频率将效果分组:
   - 高频 (>1000 次): file_written, file_content_read, command_executed
   - 中频 (100-1000 次): file_deleted, message_sent, subagent_spawned
   - 低频 (<100 次): webhook_registered, authentication_bypassed
2. 对比各组的线性可编码性（实验 1 的 R²）+ 因果可验证性（实验 4 的忠实性）
3. 分析频率梯度是否解释了线性编码质量的差异

**预期**: 参考 Merullo et al. 的发现，低频效果的线性编码质量应该显著低于高频效果。这为 CAR 的因果可解释性建立了一个**频率上限**——低于一定频率的效果可能无法通过线性约束的因果抽象来可靠解释。

## 四、可验证的研究假设

基于以上实验设计，CAR 的研究可以提出以下可验证（和可证伪的）假设:

### H1 (线性编码假设)
> 在 CAR 的执行数据中，至少 70% 的安全关键因果效果在 LLM 嵌入中被线性编码（线性探针 R² > 0.7）。

**可证伪方式**: 展示多数安全关键效果在线性探针上只有低 R²。

### H2 (因果忠实性假设)
> 对于线性可编码的安全关键效果，DAS 找到的因果子空间在交换干预中表现出 >85% 的忠实性（交换后效果按因果模型预期变化）。

**可证伪方式**: 展示即使线性可编码的效果在交换干预中也不按因果模型预期变化——说明线性相关 ≠ 因果。

### H3 (线性充分性假设)
> 对于安全关键效果，线性 τ 的 IIA 与非线性 τ 的 IIA 之间的差异（Δ）不超过 10 个百分点。

**可证伪方式**: 展示 Δ 对于某个安全关键效果显著大于 0.1——说明线性约束不够。

### H4 (频率阈值假设)
> 因果效果的线性编码质量与其在执行数据中的频率高度相关（Pearson r > 0.7），且存在约 100 次的频率阈值，低于该阈值线性编码不可靠。

**可证伪方式**: 展示低频效果也能被完美线性编码（或高频效果被非线性编码）——要么 LRH 在 CAR 中不成立，要么它不需要频率阈值。

## 五、论文可行性的诚实评估

### 5.1 需要的实验条件

| 条件 | 当前状态 | 如何获得 |
|------|---------|---------|
| 执行数据 | ❌ 零 | 需要部署 CAR 或使用模拟数据 |
| LLM 嵌入 | ❌ 零 | 需要集成 API 或开源模型 |
| 因果模型 | ⚠️ 设计完成 | 已在上文定义 |
| DAS 实现 | ❌ 未实现 | 基于 Pyvene 库构建 |

### 5.2 最低可行路径

如果无法获得大量真实执行数据，最低可行的替代方案:

1. **使用模拟数据**: 编写一个 agent 模拟器，随机或规则化地生成 (工具调用, 状态, 效果) 三元组。这不是真实的，但它可以验证方法论的可行性。

2. **使用已有的 agent 执行数据集**: 如果存在任何公开的 agent 工具调用数据集（如 SWE-Agent, OpenHands），可以使用它们作为替代。

3. **合成因果场景**: 在完全受控的合成数据上，我们知道 ground truth 的因果结构——这可以作为方法论的"概念验证"。

### 5.3 即使没有实验数据，理论部分也可以独立发表

注意：Sutter et al. (NeurIPS 2025 Spotlight) 的核心贡献是**理论性的**——证明非线性 τ 使因果抽象空洞——他们的实验只是为了展示这个现象的具体表现。

CAR 的论文可以采取类似的策略:
- **理论贡献**: 将因果抽象的线性约束引入 agent 安全领域，展示为什么这对 agent 安全是可证伪性要求的
- **框架贡献**: 提出 CAR-CA (CAR with Causal Abstraction) 框架——定义高层因果模型、表征来源、验证协议
- **初步实验**: 合成数据上的概念验证

这个组合——理论 + 框架 + 概念验证——已经是一篇完整的 NeurIPS/ICML 级别的投稿。

### 5.4 最基本的实验也足够有力

即使只有合成数据和最少的实验（实验 1 + 实验 3），也可以做出有意义的贡献：

- **实验 1 (线性可编码性)**: 展示了在 agent 安全场景中，哪些效果天然适合线性因果解释，哪些不适合——这是一个新的测量（之前没有人做过）。
- **实验 3 (线性 vs 非线性对比)**: 展示了 Sutter et al. 非线性困境在 agent 安全中的具体表现——这是将他们的理论从静态语言模型推广到动态 agent 系统。

即使完全负面的结果（"在当前的 LLM 嵌入中，因果效果没有被线性编码"）也是一个重要的发现——它意味着当前的 agent 安全系统**不能**依赖线性因果抽象来做可验证的安全解释。
