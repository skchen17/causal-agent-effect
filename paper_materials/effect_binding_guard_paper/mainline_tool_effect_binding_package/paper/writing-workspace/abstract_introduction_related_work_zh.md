# 摘要、引言与相关工作中文版

本文档是 `paper/current-usenix/main.tex` 的 Abstract、Introduction 和 Related Work 中文辅助稿。最终五项实验结果写入后，应再次核对其中的数字和措辞边界。

## 摘要

使用工具的大语言模型智能体可能在人类检查之前就提交具有安全影响的外部副作用。现有评测通常关注监控器是否拒绝了不安全调用，却很少检验其决策是否真正绑定到了该调用的实际效应、目标资源、操作类型、授权上下文和来源信息。这一区分十分关键：监控器可能只是跟随工具名称，或者通过大量弃权表现出表面上的稳健性，但当同一效应迁移到不同工具表面，或仅资源与授权发生变化时仍然失效。

我们将**工具-效应绑定（tool-effect binding）**形式化为一种提交前安全属性，并提出一个反事实压力测试框架，对上述因素进行相互独立的变化。在包含 822 个案例和 6,840 个成对关系的测试集中，已发布检查点和结构化组件表现出非平凡能力，但所有被评估的非预言方法都未能完成联合绑定。我们的参考硬规则防护器在总体上达到 `754/822 = 0.917` 的覆盖率和 `13/360 = 0.036` 的不安全预放行率；然而，在针对资源与授权的压力测试中，尽管覆盖率仍为 `221/240 = 0.921`，不安全预放行率却上升到 `74/120 = 0.617`。

受这一失败结果启发，我们实现了一个本地授权感知的提交前中介器，其中包含类型化策略、资源解析、操作语义、多资源原子化以及来源检查。在一个覆盖五个领域、共 600 个案例的测试平台上，该原型将覆盖率从 `120/600 = 0.200` 提升到 `528/600 = 0.880`，并将观察到的不安全预放行从 `12/276` 降低到 `0/276`，同时安全请求误拒绝为 `0/252`。在原始测试平台上进行人工修正后的敏感性分析仍保持零个观察到的不安全预放行，但引入了 `4/230 = 0.017` 的误拒绝率。上述结果建立的是一个受控诊断框架和本地授权合同原型，而不是生产环境安全性证明。

## 引言

工具调用将大语言模型智能体的输出转化为安全决策。一个候选调用可能发送消息、共享文件、修改日历、向协作空间发布内容，或发起交易。一旦执行，这些操作可能很难甚至无法撤销。因此，已有工作开始构建让智能体接触高风险工具和提示注入攻击的评测环境 `\cite{toolemu,agentdojo}`，并提出在规划阶段或工具调用阶段进行干预的防护方法 `\cite{toolsafe,safiron}`。

这一执行边界上的授权问题是关系性的，而不是词汇性的。向某个收件人发送消息可能得到授权，但向另一个收件人发送同一消息则未必被允许；读取文件的权限并不意味着拥有共享该文件的权限；可信用户请求与从不可信工具输出中复制出的指令也不应具有同等权限。反过来，工具名称、封装器、别名、模式以及轨迹格式可能发生变化，而预期效应保持不变。因此，一个跟随这些表面形式的监控器可能因为错误原因通过常规测试：当资源替换已经改变授权状态时，它可能仍维持原决策；而当变化仅涉及无关封装形式时，它又可能错误地改变决策。

现有防御已经解决了这一问题的重要组成部分。CaMeL 约束控制流和数据流，并利用能力机制限制未经授权的数据流 `\cite{camel}`；IPIGuard 通过预先规划的工具依赖图约束执行 `\cite{ipiguard}`；Progent 对工具调用实施可编程的最小权限策略 `\cite{progent}`；MiniScope 则为工具调用智能体重建权限层级 `\cite{miniscope}`。这些系统表明，结构化约束和显式策略是必要的。本文关注一个与之互补、且在策略执行之前发生的问题：**候选操作是否首先被正确绑定到了与策略相关的效应、资源、操作和来源？** 汇总性的攻击成功率、任务效用或二元安全准确率并不能单独识别这一属性。

我们将这一属性称为**工具-效应绑定**。考虑一个提交前中介器，它能够观察任务、可见工具接口、候选调用以及可用证据。当仅表面形式发生变化、而授权效应保持不变时，它的决策应当保持不变；当实际效应、目标资源、操作模式、授权上下文或控制来源跨越策略边界时，它的决策应当发生变化。这些要求必须联合检验：单独考察表面不变性可能奖励一个始终放行的规则，而单独考察效应敏感性又可能遗漏资源特定的授权违规。

我们通过一个反事实压力测试框架将这一思想操作化。该框架沿表面形式、效应、资源、授权、操作、来源和证据等轴组织成对案例，并报告不安全预放行、安全请求误拒绝、覆盖率和弃权率。我们将其应用于简单代理基线、已发布的 TS-Guard 与 Safiron 检查点、IPIGuard 与 CaMeL 组件、语义诊断方法，以及一个参考硬规则 Effect-Binding Guard。比较结果严格限定在本文构造的压力测试输入上，并不构成对原始系统基准结果的复现。

实验揭示了部分稳健性与联合绑定之间持续存在的差距。现有方法不能被简单归结为工具名称分类器；参考硬规则防护器在主测试集中达到 `754/822 = 0.917` 的覆盖率和 `13/360 = 0.036` 的不安全预放行率。然而，在针对资源与授权的扰动下，其不安全预放行率上升到 `74/120 = 0.617`，同时覆盖率仍保持在 `221/240 = 0.921`。这意味着防护器并非只是“不确定”，而是经常做出了错误的授权决策。该结果表明，核心瓶颈是资源和授权绑定，而不仅仅是表面不变性。

随后，我们考察能否通过将授权变成显式系统接口来缓解这一瓶颈。我们的本地提交前原型表示类型化授权上下文、解析资源别名、区分操作模式、将多资源调用展开为授权原子，并叠加来源检查。在一个覆盖邮件、日历、文件、协作空间和交易五个领域的 600 案例测试平台上，该原型将覆盖率从 `120/600 = 0.200` 提升到 `528/600 = 0.880`，并将观察到的不安全预放行从 `12/276` 降低到 `0/276`。这一结果通过了严格标签隐藏重放、资源扰动以及独立实现的参考授权器检查。另一个包含 60 个案例的人工审计发现了标签和原子修正；在原始测试平台的修正敏感性分析中，不安全预放行仍为 `0/320`，而安全请求误拒绝变为 `4/230 = 0.017`。

本文作出以下四项贡献：

1. **安全属性与测量框架。** 我们将工具-效应绑定定义为一种提交前属性，并提出反事实测试，将表面不变性与效应、资源、授权、操作及来源敏感性区分开来。
2. **跨方法诊断。** 我们表明，被评估的检查点和结构化组件具有非平凡但不完整的绑定能力，并明确区分已发布检查点压力测试、组件压力测试、诊断方法以及不可部署的上界方法。
3. **参考防护器与瓶颈。** 我们提供一个包含显式弃权机制、可检查的硬规则防护器，并证明即使决策覆盖率较高，资源与授权变化仍然构成高错误率区域。
4. **授权感知原型与审计。** 我们表明，显式授权基础设施能够显著提升受控本地中介覆盖率，并通过重放、决策路径、扰动、参考授权器和人工修正分析对结果进行验证。

本文证据的适用范围是有意受限的。反事实测试集是受控诊断工具，授权感知中介器则是在本地模拟授权合同下进行评估。本文不声称实现了完整权限系统、生产环境安全性，也不声称已在真实部署的 SaaS、浏览器、银行、邮件或协作空间服务中得到验证。

## 相关工作

**工具型智能体的安全评测。** ToolEmu 使用语言模型模拟的沙箱，在无需实例化所有外部环境的情况下，搜索跨多种工具的高风险失败 `\cite{toolemu}`。AgentDojo 提供了一个可扩展环境，用于在现实智能体任务和不可信工具数据上评估提示注入攻击与防御 `\cite{agentdojo}`。这些基准表明，端到端智能体行为会以具有安全影响的方式失败，因此评测必须同时覆盖任务效用和对抗条件。本文框架处理的是一个更窄的测量问题：它不估计整体任务结果或攻击结果，而是构造受控反事实对，以确定提交前决策实际跟随的是哪个语义变量。因此，它是可以嵌入更广泛基准中的诊断层，而不是端到端评测的替代品。

**执行前与步骤级防护器。** ToolSafe 提出 TS-Bench 和 TS-Guard，用于主动检测步骤级工具调用安全性，并通过反馈改善后续智能体推理 `\cite{toolsafe}`。Safiron 工作在规划阶段，将跨规划器适配器与基于合成轨迹训练的紧凑防护模型结合；Pre-Exec Bench 则评估检测、分类、解释和跨规划器迁移能力 `\cite{safiron}`。这些方法关注操作或规划在执行前是否存在风险。对于能够获得的模型，我们在本文自定义反事实输入上评估其已发布检查点，但不复现原始基准结果。本文的区别在于测量方式：二元安全准确率可能将表面不变性、效应敏感性、资源感知、授权敏感性和弃权混合为一个分数，而我们的压力测试格分别报告这些能力。

**针对提示注入的结构化防御。** CaMeL 在大语言模型外围构建保护层，提取可信控制流与数据流，并利用能力机制阻止未经授权的数据流 `\cite{camel}`。IPIGuard 将规划与不可信数据交互分离，并通过工具依赖图约束执行 `\cite{ipiguard}`。二者都将安全执行从无约束的模型判断转移到显式结构之上。本文认同这一系统设计动机，但研究的是不同的失败边界：在应用结构化策略之前，候选操作是否已经被映射到正确的实际效应、资源、操作、授权和来源。因此，本文关于 CaMeL 和 IPIGuard 的结果仅属于组件级自定义压力测试；这些结果既不构成完整系统复现，也不意味着这些方法在其原始评测中失败。

**授权与最小权限。** Progent 使用领域特定语言表达工具调用上的细粒度权限策略，并在运行时确定性地执行这些策略 `\cite{progent}`。MiniScope 重建工具权限层级，并将其与移动平台式权限模型结合，以约束工具调用智能体 `\cite{miniscope}`。这类工作与本文授权感知原型最为接近，因为它们显式表示权限，而不是让大语言模型在缺少约束的情况下自行推断安全性。两者的区别在于**策略表示与执行**和**绑定**：只有当候选调用被关联到正确的效应、资源、操作和来源时，策略引擎才能执行预期规则。本文的反事实框架测量这一关联，而原型则在相关授权结构已显式给出的本地合同中检验该过程。与 Progent 或 MiniScope 相比，本文原型并不是完整权限系统，也不具备它们更广泛的系统级执行范围。

**本文定位。** 相对于上述研究，本文贡献不是一个新的提示注入基准，也不是一个普遍更强的防护器或完整最小权限系统。本文对这些方法共同依赖的一个前提进行受控检验：操作边界上的决策应当跟随与策略相关的语义，而不是偶然的表面形式。同时报告不安全预放行、安全请求误拒绝、覆盖率和弃权，也可以避免将保守的不作决策错误地视为成功中介。
