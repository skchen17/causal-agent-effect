### 3.2 Real-tool effect semantics 仍有冲突

独立语义核对发现：

| 冲突类型 | 数量 | 示例 |

### 3.5 Contrastive strict split 不是实际 strict 实验

`analysis/contrastive_strict_split_qwen3-8b_scenarios_merged.json` 的实际内容是 taxonomy：

- two-form: `content_fetched`, `file_written`
- three-plus: `network_egress`, `tool_error`

它没有真正 pair-level strict leave-one-pair-out 所需字段：

- held-out pair。
- train pairs。
- pair-level strict post-FNR。
- pair-level raw FNR。
- pair-level delta FNR。
- num improved / num total strict pairs。

`analysis/analyze_contrastive_strict_split.py` 只读取 full-training multiseed 结果并按工具数量分类；没有重训 held-out pair projection。

结论：当前 P3 只完成 strict evaluability taxonomy，不支持“strict 实验完成”。

### 3.6 Multiseed 输出与新脚本 schema 不一致

`run_contrastive_multiseed.py` 会写出：

```json
{
  "config": {
    "model": "...",
    "data": "...",
    "seeds": [...],
    "dim": 128,
    "train_protocol": "full_training"
  }
}
```

但当前 `analysis/contrastive_multiseed_qwen3-8b_scenarios_merged.json` 只有：

```json
{
  "config": {
    "seeds": [0, 1, 2, 3, 4],
    "dim": 128
  }
}
```

并且 per-tool result 没有 `aggregation` 字段。说明当前 JSON 不是新脚本 schema，或者脚本未被重新运行同步。

额外脚本风险：

- `run_contrastive_multiseed.py` 的 output path 写死为 `analysis/contrastive_multiseed_qwen3-8b_scenarios_merged.json`，即使传入别的 `--model/--data`。
- `load_data()` 先用 `embeddings_*{data}*.npy` glob，可能匹配到非目标模型或 lexical-control 文件；应改成精确路径优先。
