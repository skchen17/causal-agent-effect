### 2.4 effect semantics policy

后续 AI 必须先实现统一规则，再生成样本。

| 工具/情况 | 效果规则 |
|------|------|
| `terminal` 成功提交非空 command | `command_executed=1` |
| `terminal` 被 guard/approval 阻止 | `command_executed=0`, `tool_error=1`, 并记录 `blocked_by_guard=true` |
| `terminal` 删除文件 | `command_executed=1`, `file_deleted=1` |
| `terminal` 写文件 | `command_executed=1`, `file_written=1` |
| `terminal` 读取文件 | `command_executed=1`, `file_content_read=1` |
| `terminal` curl/wget/http 请求 | `command_executed=1`, `network_egress=1`; 若取回内容则 `content_fetched=1` |
| `web_extract` 使用 `https://` URL | `network_egress=1`, `content_fetched=1`，除非显式是 cached/local 且 URL 不是外部 HTTPS |
| `web_search` 执行 query | `network_egress=1`, `search_performed=1` |
| `read_file` 成功 | `file_content_read=1` |
| `write_file` 成功 | `file_written=1` |
| `send_message` 成功 | `message_sent=1`; 若外部平台则通常 `network_egress=1` |
| `delegate_task` 成功 | `subagent_spawned=1`; memory update 只有真实记录子任务时才置 1 |
| `memory` add/replace/remove 成功 | `memory_updated=1` |

### 3.4 strict lopo 算法要求

对每个效果 `E`：

1. 找出正样本数 `>=5` 的工具集合 `T_E`。
2. 若 `|T_E| < 3`：
   - 标为 `not_evaluable`。
   - reason: leaving out the only cross-form pair leaves no cross-form positive training pairs。
3. 若 `|T_E| >= 3`，对每个 unordered pair `(A, B)`：
   - 训练 projection 时排除所有 `A-B` 正样本对。
   - 允许使用 `A-C`, `B-C`, `C-D` 等其他 pair。
   - 在 projected space 上计算 pair 相关 FNR。
   - 输出 A 和 B 两个 heldout tool 的 pre/post/delta。

pair-level JSON 示例：

```json
{
  "schema_version": "contrastive_strict_lopo_v1",
  "generated_by": "run_contrastive_strict_lopo.py",
  "config": {
    "model": "qwen3-8b",
    "data": "scenarios_merged",
    "seed": 0,
    "dim": 128,
    "min_positive_per_tool": 5
  },
  "summary": {
    "num_evaluable_effects": 2,
    "num_strict_tool_cases": 68,
    "num_improved": 40,
    "mean_delta_fnr": 0.16
  },
  "effects": {
    "network_egress": {
      "status": "evaluable",
      "tools": ["send_message", "terminal", "web_fetch", "web_search"],
      "pairs": [
        {
          "heldout_pair": ["terminal", "web_fetch"],
          "train_pairs_excluded": [["terminal", "web_fetch"]],
          "tool_results": [
            {
              "tool": "terminal",
              "n_positive": 29,
              "raw_fnr": 0.4138,
              "strict_post_fnr": 0.1724,
              "delta_fnr": 0.2414
            }
          ]
        }
      ]
    }
  }
}
```

DONE 标准：

- `analysis/contrastive_strict_lopo_qwen3-8b_scenarios_merged.json` 存在。
- JSON 有 pair-level fields。
- summary 的 `num_improved/num_strict_tool_cases/mean_delta_fnr` 可由 pair rows 重新计算。
- `paper/main.tex` 的 strict claim 只引用该文件。

如果复用旧 `analysis/ablation_qwen3-8b_scenarios_merged.json`：

  - `analysis/normalize_contrastive_strict_from_ablation.py`

## 4. P2 Causal-Chain：第三轮执行要求

### 4.1 当前状态

已通过：

- 4 effects x 5 conditions 数据存在。
- Qwen3-8B causal-chain embeddings 长度匹配。
- LOTO/ToolProxyGap pilot 结果可读。

未通过：

- `wrong_chain_type` 全部缺失/null。
- `authorization_flip=0`。
- 无 mechanism metrics。
- 当前 task-causal-chain 文本把 observed effects 直接写成 authorized effects，可能造成 label leakage。

### 4.2 建议生成 v2 数据

不要覆盖旧文件，先输出：

- `data/causal_chain_conditioning_v2.jsonl`
- `analysis/causal_chain_conditioning_v2_manifest.json`

建议 condition 设计：

| condition | 说明 |
|------|------|
| raw | 原始文本 |
| tool_only | 工具名/动作控制 |
| effect_chain | 给效果链，不给授权 |
| task_causal_chain | 给任务目标、候选效果、授权 envelope |
| wrong_effect_omission | 漏写真实效果 |
| wrong_effect_flip | 把真实效果替换成错误效果 |
| wrong_authorization_flip | 效果事实不变，授权状态反转 |

每条 wrong-chain 样本必须有：

```json
{
  "condition": "wrong_authorization_flip",
  "condition_family": "wrong_chain",
  "wrong_chain_type": "authorization_flip",
  "true_effects": {"network_egress": 1},
  "stated_effects": {"network_egress": 1},
  "true_authorization": {"network_egress": false},
  "stated_authorization": {"network_egress": true},
  "chain_valid": false
}
```

### 4.3 避免 authorization 伪标签

如果没有人工授权标签，不要把 `context_type` 或 observed effects 直接写成 gold authorization。

允许做法：

- 使用 `authorization_source="synthetic_probe_condition"`。
- 使用 `authorization_confidence="constructed"`。
- 在论文中写：constructed authorization perturbation, not ground-truth deployment authorization。

禁止做法：

- 将 `observed effects == authorized effects` 写成真实授权。
- 将 authorization_flip 的结果写成真实越权防御能力。

### 4.4 机制指标

新增脚本：

- `analysis/analyze_causal_chain_mechanism.py`

输出：

- `analysis/causal_chain_mechanism_qwen3-8b_v2.json`
- `analysis/causal_chain_mechanism_qwen3-8b_v2.md`

至少包括：

| 指标 | 目的 |
|------|------|
| LOTO max held-FNR | 与当前结果兼容 |
| ToolProxyGap | 当前主指标 |
| same-effect cross-tool distance | 检查表征是否按 effect 聚合 |
| tool discriminator accuracy on E=1 | 检查工具信息是否仍可分 |
| effect probe AUC/F1 | 排除性能退化 |
| wrong-chain induced error by type | 区分 omission/flip/authorization_flip |

DONE 标准：

- `wrong_authorization_flip` 样本数非零。
- 每个 wrong-chain type 都有 type-wise result。
- mechanism JSON 中有 distance/discriminator 指标。
- paper 中只写 pilot / constructed perturbation，不写真实授权防御。
