### 0.1 核心原则

当前项目后续统一围绕 **CEG-Auth / AuthTrace-Guard 方法论文** 展开：

> Authorization-conditioned realized-effect monitoring should be performed over label-hidden execution evidence, not over tool names, LLM self-audits, or oracle trace labels. CEG-Auth / AuthTrace-Guard should infer realized effects from raw traces, localize supporting evidence, estimate uncertainty, and make selective action-level authorization decisions under held-out tool-surface and trace-family shifts.

中文：

> Agent 越权检测不应依赖工具名、LLM 自审计或带标签 trace 字段，而应在任务授权包络 `A(c)` 下，从 label-hidden 执行证据中推断实际发生的 realized effects，定位证据、估计不确定性，并在 action level 做 `ALLOW / DENY / ABSTAIN / ASK_USER` 决策。

当前执行原则：

1. **只主动推进新方法**：优先完成 `F_c` 约束编译、shadow execution、trace-locked replay、guarded real replay、pre-commit blocking benchmark。
2. **旧内容只复用不扩展**：旧实验结果只作为问题动机、负结果、baseline 约束或附录材料；除非服务 T102-T114，不再重跑旧 LOTO/pIIA/contrastive/Auth-SafeInv。
3. **论文写作暂停到真实评测后**：下一轮写作不再直接重建 method paper；必须先完成 AgentDojo/AuthGraph-aligned real-scenario evaluation gate。Path A 和旧 verifier-assisted 稿件继续暂停。
4. **验收指标转向 prevention**：核心指标从旧 row-level FNR/FPR 转为 `Unauthorized Committed Effect Rate`, `Pre-effect Block Rate`, `U-Allow`, `FDeny`, `Abstain`, `Coverage`, `Shadow-real Divergence`。

### 0.2 当前论文主张

方法论文版本：

> We propose **CEG-Auth / AuthTrace-Guard**, a label-hidden realized-effect authorization framework for tool-using LLM agents. Given a task context `c`, an authorized effect envelope `A(c)`, and an agent's proposed intent, the framework compiles a future trajectory constraint `F_c`, validates the intended trajectory through shadow execution, infers pending realized effects from label-hidden execution evidence, and replays only the locked trajectory in the real environment under pre-commit guards. The action-level policy aggregates risk only over effects outside `A(c)` and reports `U-Allow / FDeny / Abstain / Coverage / Selective Risk`. Existing Path A diagnostics are reused as motivation and failure evidence: surface-form fragmentation motivates held-out-surface evaluation; label-hidden trace degradation motivates raw-evidence inference; row-to-action failures motivate selective action-level policy.

### 0.3 贡献组织

方法论文的四个核心贡献目标：

1. **Label-hidden realized-effect inference**：从 raw execution trace / evidence graph 中预测 `p(effect)`，不得使用 `verified_effects`, `unauthorized_effects`, `effect_diff`, `candidate_effect_present` 等 label 或 near-label 字段。
2. **Authorization-conditioned selective policy**：只对 `e notin A(c)` 聚合风险，输出 `ALLOW / DENY / ABSTAIN / ASK_USER`，主指标为 action-level `U-Allow`, `FDeny`, `Abstain Rate`, `Coverage`, `Selective Risk`。
3. **Surface-held-out robustness**：在同一 effect 的不同真实 surface、tool family、provider/schema 和 trace family 上做 held-out evaluation，证明方法不是 tool proxy 或 schema shortcut。
4. **Evidence localization and uncertainty**：为每个 effect 输出支持证据片段/子图和不确定性，使安全判断可审计，并支持 abstention / human review / sandbox replay。

旧组件处置：
- Path A 三层高估结果 → 方法论文 motivation / diagnostic background；
- pIIA → supporting diagnostic，不作因果证明；
- contrastive projection → observed-pair upper bound / negative contrast；
- T54-T56 gate failures → 说明纯表征修复不足，转向 execution-evidence method；
- T68/T69/T70/T73 → 方法设计约束：label-hidden、action-level、强 baseline、非退化 calibration。

### 0.4 主会接收验收线

后续工作以主会接收线为目标。方法论文最低验收标准：

| 维度 | 主会接收线 |
|------|------------|
| Threat model | 明确 task authorization envelope、observable realized effects、attacker capability、trusted trace collector 和排除范围 |
| 方法 | CEG-Auth / AuthTrace-Guard 有可实现算法：EventExtract → EffectInfer → AuthCompare → SelectivePolicy |
| 主实验 | label-hidden raw trace 主结果，不以 full-label verifier 作为方法性能 |
| Robustness | leave-one-surface/tool-family/trace-family/provider-schema held-out split |
| Action policy | 主表报告 `U-Allow / FDeny / Abstain / Coverage / Selective Risk`，不得只报 row-level FNR/FPR |
| Baseline | 对齐 raw-status boundary、provenance boundary、deterministic rules、LLM judge、flat trace classifier、event sequence、graph ablations |

| Claim boundary | 不声称部署安全认证；只声称在 mediated/observable effects 和测试分布内降低越权允许风险 |

## 1. 审稿结论与必须修正的问题

### 1.1 当前严格审稿判断

综合两轮严格审稿意见和 T57/T58/T59/T61/T62/T63/T64/T65/T73 新证据，当前版本按主会标准维持 **Borderline / Major Revision**，前提是论文明确写成 verifier-assisted controlled/protocol study，而不是部署安全认证。T59 增加了真实工具代码 grounding，但也暴露 schema-to-real-agent-local-trace 漏检；T61 证明 provider API trace 管线可扩展且 static verifier 会漏检 provider effects；T62 进一步把阈值从 ex-post curve 改成 validation trace groups 上选择、held-out trace groups 上测试；T63 扩展到 web/search/browser/messaging local adapters；T64 在无 provider key 条件下补充真实 outbound HTTPS 和本地 webhook protocol trace evidence；T65 补充 file-backed headless Chrome DOM/JS runtime evidence；T73 则说明 action-level calibration 仍未解决。当前仍不能进一步上调为 main-conference ready，因为项目仍缺 provider-backed search、SaaS messaging、HTTP browser automation 和 deployed-agent runtime validation。主要问题不是项目方向不成立，而是：

1. 论文主张和证据强度不完全匹配；当前证据更支持 controlled diagnostic study，而不是通用 agent safety framework。
2. 数据规模和 cell-level positive count 偏小，若干关键 held-out FNR 只能作为强预警，不能作为稳健估计。
3. 数据以模板和 LLM 合成为主；Auth-SafeInv 已有 controlled observed/sandbox/static execution traces，T59 加入了 `real-agent-tools` Hermes 注册和 local-adapter traces，T61 加入了 120 条 DeepSeek provider API observed traces，T62 完成了 trace-group validation threshold calibration，T63 加入 300 条 web/search/browser/messaging local-adapter traces，T64 加入 300 条 key-free live/protocol traces，T65 加入 120 条 file-backed browser-runtime traces，但仍缺 broad direct handler/API-backed live deployed-agent logs。
4. full-training contrastive projection 依赖已观察到的 cross-form positive pairs，不能作为 coverage-missing / zero-shot mitigation 主证据。
5. pIIA 是 probe-mediated activation transfer diagnostic，不能写成标准 SCM-based IIA 或因果抽象证明。
6. 理论部分主要是 risk accounting 与 conditional analysis，不足以支撑“safety theorem”式核心贡献。
7. baseline、统计不确定性、阈值选择、seed variance、pIIA controls、action-level metrics/calibration 和 reproducibility 材料已有可审计 artifacts；当前主阻塞转为 strict mitigation 证据不足、action-level policy 未解和外部有效性不足。

### P2. Causal-Chain Conditioning 机制实验

**优先级**：高  
**目标时间**：3-5 天 pilot  
**状态**：DONE for pilot / mechanism diagnostic

研究问题：

> 因果链信息是否能改变 LLM 对工具调用的表征组织方式？当输入显式或半显式地呈现任务-动作-效果链时，模型表征是否从工具表面形式聚类转向因果效果聚类？

这不是先定一个运行时安全框架，而是研究“因果链信息对表征的影响”。

实验设计：

选择首批效果：

- `content_fetched`
- `file_written`
- `network_egress`
- `tool_error`

构造输入版本：

| 版本 | 内容 | 目的 |
|------|------|------|
| Raw | 当前原始工具调用描述 | 基线 |
| Tool-only control | 强调工具和动作，不给效果链 | 控制工具表面信息 |
| Effect-chain | 给出候选动作及其因果效果 | 测试效果链是否重组表征 |
| Task-causal chain | 给出任务目标、授权效果、候选动作效果 | 测试任务因果上下文 |
| Wrong/scrambled chain | 给出错误或打乱的效果链 | 检查模型是否盲信显式链 |

指标：

- LOTO heldout FNR。
- ToolProxyGap。
- pIIA-Drop。
- 同效果跨工具表示距离。
- 工具 discriminator accuracy on E=1。
- 效果 probe F1 / AUC。
- wrong-chain condition 下的错误诱导程度。

判定逻辑：

- 若 causal-chain conditioning 降低 ToolProxyGap 且不显著增加 wrong-chain 脆弱性：可作为 input-side mitigation。
- 若只在 effect-chain 生效但 wrong-chain 也强烈误导：说明 LLM 可被显式链操纵，需要 verifier 或 consistency check。
- 若完全无效：说明碎片化更像表征/训练层问题，contrastive projection 或数据训练更关键。

验收标准：

- 至少完成 4 个效果、5 种输入版本的嵌入与 LOTO 评估。
- 形成 `analysis/causal_chain_conditioning_*.json` 和一份简短分析文档。
- 决定是否把该方向升级为第二个方法贡献。

### P10.1 新方法任务执行原则

从 2026-05-31 起，future-constrained CEG-Auth / AuthTrace-Guard 后续任务必须严格围绕当前核心主张和主会审稿要求执行，不再发散到旧 monitor 路线或泛化的 agent safety 实验。

**当前核心主张**：

> Tool-using agents should be authorized by future-constrained realized-effect trajectories: compile task authorization and agent intent into `F_c`, validate the intended trajectory in shadow/staged execution, replay only the locked trajectory with prefix guards, and commit only effects inside `A(c)`.

后续每个实验必须满足以下原则：

1. **主张对齐**：实验必须直接检验 `F_c` 编译、shadow/staged execution、trace-locked replay、prefix guard、safe substitution、pre-commit blocking、或外部有效性中的至少一项。不能只因为“相关”就新增旧 LOTO、pIIA、contrastive、post-hoc graph monitor 或普通 verifier 实验。
2. **能说明有效性**：每个实验必须说明它支持或证伪哪一句方法主张。若只能证明接口自洽，必须标注为 prototype/interface evidence；若能证明真实阻断，必须报告真实 side-effect boundary 和 commit 前阻断位置。
3. **顶会证据标准**：主结果必须报告 N、case taxonomy、positive/negative or authorized/unauthorized counts、exact/Wilson CI、threshold/decision rule、artifact source 和失败样例。完美的 0/1 指标不得裸报，必须带置信区间和限制。
4. **强边界控制**：本地 staged/dry-run 结果不得写成 provider-backed 或 deployed-runtime 结果；rule/gold-envelope 结果不得写成 LLM compiler 泛化；simulated browser submit 不得写成 HTTP browser automation。
5. **强 baseline / ablation**：后续方法有效性必须通过 ablation 证明，不得只展示 full pipeline。至少比较 without shadow、without replay lock、without prefix guard、without staging、tool-rule、raw-status、LLM judge 或 pre-action-only。
6. **外部有效性优先级**：只在本地统计审计和更真实本地 side-effect boundary 完成后，再推进 provider/SaaS/browser/deployed-runtime 资源实验。若资源不可得，论文必须定位为 controlled local prevention study。
7. **写作同步**：每完成一个实验，必须同时更新本规划、结果报告、claim boundary 和可写/不可写主张表。论文文字只能引用已落盘 artifact 中可追溯的数字。
8. **失败也保留**：若 LLM compiler over-permission、prefix guard false denial、shadow-real divergence 或 ablation failure 出现，不得修饰为成功；应作为方法边界或 negative evidence 写入。

**2026-05-31 方法方案更新**：

当前 CEG-Auth / AuthTrace-Guard 不应只写成 post-hoc monitor。为支持“在越权执行前阻断”，主线加入 **Future-Constrained Shadow Execution**：

```text
c, A(c), agent intent
  -> F_c: future trajectory constraint
  -> shadow execution tau_s
  -> causal evidence graph G_s
  -> pending effects Omega_s and uncertainty
  -> selective policy
  -> replay-locked plan pi
  -> guarded real replay with safe substitution sigma
  -> staged final commit
```

这一路线的核心贡献不是 graph，而是：

1. 将 task authorization 和 agent intent 编译为可执行未来轨迹约束 `F_c`；
2. 用影子执行产生 label-hidden evidence graph，并在真实副作用前验证 pending effects；
3. 将通过验证的影子轨迹编译为 trace-locked replay plan `pi`；
4. 真实环境中不再让 LLM 二次输出，而由受控 executor 按 `pi` 复放，并在每个 side-effect boundary 做 prefix guard；
5. 对不可确定安全的操作输出 `ABSTAIN/ASK_USER`，而不是在 all-deny/all-allow 间塌缩。

必须保持条件性表述：若工具绕过 mediation、真实 provider 不支持 staging/dry-run、`F_c` 过度宽松、真实值替换改变 effect、或 pending effects 不可观测，则不能声称完全阻断。
