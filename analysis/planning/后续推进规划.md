### 0.1 核心原则

当前项目后续统一围绕 **Path A: evaluation/diagnostic paper** 展开：

> Agent safety monitoring evaluation is systematically over-optimistic at three layers: (1) tool-surface fragmentation causes coverage-missing FNR for representation-side monitors; (2) structured trace labels can make verifiers appear stronger than they are; (3) row-level metrics do not translate to action-level safety. We define Auth-SafeInv as an action-level evaluation target and provide a constructive framework with honest limits.

中文：

> Agent 安全监控评估在三个层面系统性地高估安全性：(1) 工具表面形式碎片化导致表征侧监控器在覆盖缺失时漏检；(2) 结构化trace标签字段让verifier看起来比实际更强；(3) row-level指标不能直接翻译为action-level安全。我们定义Auth-SafeInv作为action-level评估目标，并提供有诚实边界的框架。

### 0.2 当前论文主张

Path A 版本：

> We introduce **Auth-SafeInv**, an action-level evaluation target for authorization-conditioned realized-effect monitoring in LLM agents. Using linear probes trained on LLM representations, we diagnose **surface-form fragmentation**: the same causal effect is encoded differently across tool surface forms, causing high false negative rates under coverage gaps. We then show that safety evaluation can be **over-optimistic at three layers**: (1) tool-surface layer — LOTO stress tests reveal FNR up to 0.80; (2) trace-label layer — removing structured label fields from traces degrades verifier performance; (3) action-level layer — row-level FNR/FPR metrics do not translate to safe action-level allow/deny policies. Pure representation-side repair (contrastive projection, schema conditioning, decomposed verification) fails to beat strong baselines under strict held-out protocols. A verifier-assisted execution monitor (EffectVerif-AuthMonitor) works under controlled settings but faces unresolved action-level calibration and external validity limits. We provide a constructive evaluation framework, three-layer diagnostic evidence, and honest gate-failure reporting.

### 0.3 贡献组织

Path A 的四个核心贡献：

1. **Auth-SafeInv evaluation target**：将 authorization-conditioned realized-effect monitoring 定义为可操作的评估对象，包含 A(c)、Omega(a,t)、U(c,a,t) 的形式化定义和 FNR/ToolProxyGap 指标体系。
2. **Surface-form fragmentation diagnosis**：用线性探针 + LOTO split 系统展示同一 causal effect 在不同 tool surface 下的表征碎片化——这是当前外部文献中独一无二的 representation-level 发现。
3. **Three-layer over-optimism evidence**：Tool-surface layer (LOTO FNR) → Trace-label layer (T69 label-hidden degradation) → Action-level layer (T68/T73 row-to-action breakdown)。
4. **Constructive framework with honest gate-failure reporting**：EffectVerif-AuthMonitor 在 controlled setting 可行但 pure representation repair gate 失败、action-level calibration 未解决、raw-status boundary competitive。

旧组件降级方案：
- pIIA → supporting diagnostic (appendix)
- contrastive projection → observed-pair upper bound, not main method
- causal-chain conditioning → appendix diagnostic
- theory → risk accounting framing, not "safety theorem"

## 1. 审稿结论与必须修正的问题

### 1.1 当前严格审稿判断

综合两轮严格审稿意见和 T57/T58/T59/T61/T62/T63/T64/T65/T73 新证据，当前版本按主会标准维持 **Borderline / Major Revision**，前提是论文明确写成 verifier-assisted controlled/protocol study，而不是部署安全认证。T59 增加了真实工具代码 grounding，但也暴露 schema-to-real-agent-local-trace 漏检；T61 证明 provider API trace 管线可扩展且 static verifier 会漏检 provider effects；T62 进一步把阈值从 ex-post curve 改成 validation trace groups 上选择、held-out trace groups 上测试；T63 扩展到 web/search/browser/messaging local adapters；T64 在无 provider key 条件下补充真实 outbound HTTPS 和本地 webhook protocol trace evidence；T65 补充 file-backed headless Chrome DOM/JS runtime evidence；T73 则说明 action-level calibration 仍未解决。当前仍不能进一步上调为 main-conference ready，因为项目仍缺 provider-backed search、SaaS messaging、HTTP browser automation 和 deployed-agent runtime validation。主要问题不是项目方向不成立，而是：

1. 论文主张和证据强度不完全匹配；当前证据更支持 controlled diagnostic study，而不是通用 agent safety framework。
2. 数据规模和 cell-level positive count 偏小，若干关键 held-out FNR 只能作为强预警，不能作为稳健估计。
3. 数据以模板和 LLM 合成为主；Auth-SafeInv 已有 controlled observed/sandbox/static execution traces，T59 加入了 `real-agent-tools` Hermes 注册和 local-adapter traces，T61 加入了 120 条 DeepSeek provider API observed traces，T62 完成了 trace-group validation threshold calibration，T63 加入 300 条 web/search/browser/messaging local-adapter traces，T64 加入 300 条 key-free live/protocol traces，T65 加入 120 条 file-backed browser-runtime traces，但仍缺 broad direct handler/API-backed live deployed-agent logs。
4. full-training contrastive projection 依赖已观察到的 cross-form positive pairs，不能作为 coverage-missing / zero-shot mitigation 主证据。
5. pIIA 是 probe-mediated activation transfer diagnostic，不能写成标准 SCM-based IIA 或因果抽象证明。
6. 理论部分主要是 risk accounting 与 conditional analysis，不足以支撑“safety theorem”式核心贡献。
7. baseline、统计不确定性、阈值选择、seed variance、pIIA controls、action-level metrics/calibration 和 reproducibility 材料已有可审计 artifacts；当前主阻塞转为 strict mitigation 证据不足、action-level policy 未解和外部有效性不足。

### 1.2 投稿前红线

以下问题不解决，不应投主会：

- 不得把 LOTO FNR 当作真实部署 FNR 使用。
- 不得把 pIIA 写成标准 Geiger IIA 或完整因果证明。
- 不得把 synthetic controlled study 写成当前所有 LLM/agent 的普遍结论。
- 不得把 full-training contrastive projection 写成未知工具或 coverage-missing 场景下的安全修复。
- 不得把当前实验外推到 context framing、language variation、semantic reframing，除非补对应实验；当前主张应限定为 tool-surface fragmentation。
- 不得把 `real_tool_scenarios_v2` 写成真实 agent execution validation；它只是 schema/effect semantic proxy。
- 不得把 verifier-assisted monitoring 写成泛化的“新 agent defense 已解决问题”；当前最稳定位是 effect-verification layer / monitor-level framework。
- 不得只用文字声称区别于 AttriGuard / CausalArmor / ClawGuard / ARGUS；论文必须明确比较判断对象、输入信号和失败模式。
- 不得只报告 candidate-effect row 指标而完全不报告 action-level allow/deny 风险；真实 monitor 最终判断的是一次 action 是否应允许。
- 不得把 full trace verifier 结果写成 label-independent execution evidence，除非补 full / label-hidden / minimal-evidence trace ablation。
- 不得使用 `safety theorem`, `representation-level prerequisite`, `causal intervention evidence` 等会让审稿人期待强保证的措辞，除非上下文明确限定。
- 所有主文数字必须能追溯到脚本或 JSON 输出。
- 所有 N+ 很小的关键结论必须报告置信区间或明确标注为描述性结果。
- 所有 FNR/FPR/AUC 主结果必须报告阈值选择规则、正负样本数、seed variance 或 confidence interval。
- 2026 年论文、事件、benchmark、模型版本必须逐条查证。

### P2. Causal-Chain Conditioning 机制实验

**优先级**：高  
**目标时间**：3-5 天 pilot  
**状态**：DONE for pilot / mechanism diagnostic

研究问题：

> 因果链信息是否能改变 LLM 对工具调用的表征组织方式？当输入显式或半显式地呈现任务-动作-效果链时，模型表征是否从工具表面形式聚类转向因果效果聚类？

这不是先定一个运行时安全框架，而是研究“因果链信息对表征的影响”。

实验设计：

选择首批效果：

- `content_fetched`
- `file_written`
- `network_egress`
- `tool_error`

构造输入版本：

| 版本 | 内容 | 目的 |
|------|------|------|
| Raw | 当前原始工具调用描述 | 基线 |
| Tool-only control | 强调工具和动作，不给效果链 | 控制工具表面信息 |
| Effect-chain | 给出候选动作及其因果效果 | 测试效果链是否重组表征 |
| Task-causal chain | 给出任务目标、授权效果、候选动作效果 | 测试任务因果上下文 |
| Wrong/scrambled chain | 给出错误或打乱的效果链 | 检查模型是否盲信显式链 |

指标：

- LOTO heldout FNR。
- ToolProxyGap。
- pIIA-Drop。
- 同效果跨工具表示距离。
- 工具 discriminator accuracy on E=1。
- 效果 probe F1 / AUC。
- wrong-chain condition 下的错误诱导程度。

判定逻辑：

- 若 causal-chain conditioning 降低 ToolProxyGap 且不显著增加 wrong-chain 脆弱性：可作为 input-side mitigation。
- 若只在 effect-chain 生效但 wrong-chain 也强烈误导：说明 LLM 可被显式链操纵，需要 verifier 或 consistency check。
- 若完全无效：说明碎片化更像表征/训练层问题，contrastive projection 或数据训练更关键。

验收标准：

- 至少完成 4 个效果、5 种输入版本的嵌入与 LOTO 评估。
- 形成 `analysis/causal_chain_conditioning_*.json` 和一份简短分析文档。
- 决定是否把该方向升级为第二个方法贡献。
