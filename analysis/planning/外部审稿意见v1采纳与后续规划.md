## 1. 结论与 Path A 决策

这轮外部审稿意见应当 **基本采纳**。它没有否定项目主线，反而指出了更稳的主会定位。

> 不把论文写成”又一个 agent 防御方法”，而是写成 **authorization-conditioned effect-level safety evaluation + surface-form fragmentation diagnostic + three-layer over-optimism evidence + constructive framework with honest limits**。

**2026-05-22 Path A 决策**：基于最新外部文献搜索（PACT, Alignment Contracts, ARM, AgentTrust, Parallax, ECA 等 2026 密集出现），provenance/effect-trace monitoring 方向已非常拥挤。继续作为 verifier-assisted method paper 投稿 novelty 会被稀释。因此选择 **evaluation/diagnostic paper** 路线。详见 `analysis/path_a_convergence_analysis_2026-05-22.md`。

当前项目最有辨识度的贡献仍是：

1. **Auth-SafeInv**：以任务授权包络 `A(c)` 和 realized effects `Omega(a,t)` 定义 unauthorized-effect FNR/FPR——这是独特的 evaluation target。
2. **Surface-form fragmentation**：同一安全相关 effect 经不同 tool surface 实现时，representation-side monitor 在 coverage-missing stress test 中漏检——外部文献中找不到对应物。
3. **Three-layer over-optimism**：Tool-surface (LOTO) → Trace-label (T69) → Action-level (T68/T73)——系统性展示当前评估如何高估安全性。
4. **Pure representation repair gate failure**：T54/T55/T56 三个负结果——这对审稿人是强诚实信号。
5. **Constructive framework with honest limits**：T64/T65 展示 verifier-assisted monitoring 在 controlled setting 可行，但 T68/T69/T70/T73 诚实地暴露了其局限。

## 3. 当前项目与外审意见的差距

### 3.1 已基本满足

- 论文已经把 pure representation mitigation 降级：T51/T54/T55/T56 均显示 strict pure-method gate 未通过。
- T57-T64 已经提供 verifier-assisted framework evidence：
  - T57 static trace-calibrated verifier；
  - T58 controlled execution traces；
  - T59 real-agent-tools local-adapter stress test；
  - T61 DeepSeek provider API traces；
  - T62 validation-selected thresholds；
  - T63 broader local adapters；
  - T64 key-free live HTTP / local webhook protocol traces。
- 统计和 artifact 可追溯性已有基础：`reproduce_auth_safeinv.sh` 与 result-source appendix 覆盖 T39-T73。

### 3.2 仍未满足

1. **Related Work 缺差异矩阵**  
   `paper/main.tex` 目前只有相关工作段落，还没有系统比较“判断对象、主要信号、本文差异”。

2. **Verifier-assisted monitoring 还不像明确方法**  
   当前论文写出了结果和动机，但缺少 `EffectVerif-AuthMonitor` 的算法、接口、trace schema、effect taxonomy、failure modes。

3. **缺与 AttriGuard / CausalArmor / ClawGuard / ARGUS 的对照实验或 conceptual ablation**  
   目前只能文字区分，审稿人仍可能认为 verifier-assisted monitoring 是已有 runtime defense 的自然组合。

4. **Verifier 独立性还不够强**  
   需要证明 execution verifier 不是读到 `effect_name`、`event_type`、`policy_decision` 这类标签字段。T64 强化了 live/protocol evidence，但没有做 full / label-hidden / minimal-evidence trace ablation。

5. **指标仍偏 candidate-effect row**  
   真实 agent monitor 最终要判断一次 action allow/deny。主文应加入 action-level metrics：
   - Unauthorized Action Allow Rate；
   - Authorized Action False Denial Rate；
   - Macro unauthorized-effect FNR；
   - Macro authorized/absent-effect FPR；
   - per-effect / per-tool-family breakdown。

6. **T64 尚未写入论文主文**  
   `paper/main.tex` 当前 verifier table 仍到 T63，abstract 和 limitations 也未包含 T64 的 live HTTP / local webhook protocol 结果。

## 4. 新阶段优先级

### P0：先修论文定位与相关工作边界

**目标**：让审稿人立即看懂本文不是 AgentDojo/ASB/ToolEmu/ClawGuard/ARGUS 的重复。

具体任务：

- 新增 Related Work difference matrix。
- 在 Introduction 的 contribution list 中明确贡献排序：
  1. Auth-SafeInv evaluation target；
  2. surface-form fragmentation failure mode；
  3. ToolProxyGap / pIIA diagnostics；
  4. verifier-assisted authorization monitoring framework；
  5. contrastive projection as observed-pair upper bound。
- 删除或弱化任何“new defense solves agent safety”式表述。

验收标准：

- 表中每个相关工作类型都明确“判断对象”和“本文不同判断对象”。
- 论文不把 verifier-assisted monitoring 写成通用 runtime defense，而写成 effect-verification layer / monitor-level framework。

### P1：形式化 EffectVerif-AuthMonitor

**目标**：把 verifier-assisted route 从“实验现象”变成可复现方法。

建议方法定义：

```text
Inputs:
  task context c
  authorized effect envelope A(c)
  tool call a
  surface form S
  arguments x
  execution trace t

Effect verifier:
  Omega_hat = VerifyEffects(a, S, x, t)

Authorization checker:
  U_hat = Omega_hat \ A(c)

Decision:
  DENY if U_hat is non-empty, otherwise ALLOW
```

论文/代码规划：

- 在 `paper/main.tex` 增加算法框或伪代码。
- 在 appendix 或 analysis 文档中定义 trace schema：
  - `tool_call.name`
  - `arguments`
  - `surface_form`
  - `execution_status`
  - `file_diff`
  - `http_request`
  - `http_response`
  - `stdout`
  - `stderr`
  - `message_receipt`
  - `provider_status`
  - `authorized_effects`
  - `verified_effects`
- 定义 effect taxonomy 与 failure modes：
  - safe-looking tool name but trace causes network egress；
  - legitimate call reason but extra side effect；
  - shell/API equivalent effect；
  - provider success hidden from static rule；
  - partial failure with partial side effect。

验收标准：

- 读者不需要读代码就能复现方法接口。
- 方法边界明确：它依赖 effect verifier，不承诺 verifier 完美，不等同部署安全认证。

### P2：新增 action-level metric

**目标**：把 candidate-effect row 评估补成 action-level monitor 评估，方便和 agent security benchmark / runtime defense 对话。

代码任务建议：

- 新增脚本：`analysis/auth_action_level_metrics.py`。
- 输入：
  - `data/auth_trace_effect_schema_conditioned_*.jsonl`
  - 对应 T62/T63/T64 validation-selected prediction JSON。
- 按 `trace_id` 或原始 action id 聚合 candidate effects。
- Ground truth：
  - action is unauthorized if `verified_effects \ A(c)` 非空；
  - monitor denies if predicted unauthorized present effects 非空。
- 输出：
  - Unauthorized Action Allow Rate；
  - Authorized Action False Denial Rate；
  - per-tool-family action allow/deny rates；
  - macro unauthorized-effect FNR/FPR 保留为辅助。

验收标准：

- 至少覆盖 T58、T59、T61、T63、T64。
- 结果输出 `.json/.md`，并进入 result-source appendix。

### P3：Verifier 独立性消融

**目标**：排除 verifier 从标签字段读答案的替代解释。

代码任务建议：

- 新增脚本：`analysis/build_trace_ablation_views.py`。
- 对每个 trace 生成三种 view：
  1. `full_trace`：当前完整 trace；
  2. `label_hidden_trace`：移除 `effect_name`, `event_type`, `policy_decision`, `verified_effects`, `unauthorized_effects` 等标签字段；
  3. `minimal_evidence_trace`：只保留 low-level evidence，如 file diff、HTTP request/response、exit code、stdout/stderr、provider status、message receipt。
- 用同一 T62 validation-selected threshold policy 评估三种 view。

验收标准：

- minimal evidence trace 明显优于 static verifier，才能强写“execution evidence is necessary/useful”。
- 若 minimal evidence trace 明显退化，则论文必须把强结果限定为 structured trace verifier，而不是 raw execution evidence。

### P4：与现有 defense 的 conceptual / empirical ablation

**目标**：证明本文补的是 realized-effect gap，而不是重复 ClawGuard/ARGUS/AttriGuard。

建议 baseline：

- `pre_action_rule_only`：只看 user objective、tool name、arguments、policy rule，不看 execution trace。
- `provenance_only`：只判断 tool call 是否由 trusted context 支持，不判断实际 effect。
- `action_attribution_proxy`：模拟 counterfactual tool-call survival，只判断调用是否仍会发生，不验证 effect。
- `effect_verif_authmonitor`：execution trace -> realized effects -> authorization。

建议 stress cases：

- safe-looking tool name but trace causes network egress；
- legitimate call reason but extra side effect；
- shell command and API tool produce equivalent effect；
- provider API returns success but static rule cannot infer remote effect；
- partial failure with partial side effect。

验收标准：

- 不需要复现 ClawGuard/ARGUS/AttriGuard 原系统；但 baseline 输入权限和判断对象必须写清楚。
- 结果应展示“看不到 trace 的方法会漏掉某类 realized effect”，而不是泛称已有方法失败。

### P5：T64/T65/T73 进入论文，但保持边界

**目标**：把最新外部有效性 evidence 和 action-level negative diagnostic 写进论文，同时不扩大结论。

要写成：

- T64 adds key-free live/protocol traces: real outbound HTTPS and local webhook protocol I/O.
- Execution verifier validation-selected held-out test FNR/FPR = 0.0/0.0 (N+=197,N-=1170).
- Static verifiers FNR/FPR = 0.6294/0.0462.
- T65 adds file-backed headless Chrome DOM/JavaScript runtime traces; it is browser-runtime evidence, not HTTP browser networking.
- T73 shows simple action-level false-denial-constrained threshold calibration can collapse to all-allow.
- These strengthen controlled/protocol evidence but also sharpen the action-policy limitation.

不能写成：

- provider-backed search/SaaS messaging validation；
- HTTP browser automation validation；
- deployed-agent runtime validation；
- full external-service/deployed-runtime result。

### P6：外部有效性 → 明确 limitation（不再追求补齐）

外部审稿意见表明，即便继续补 provider-backed traces，如果论文没有方法接口、相关工作差异矩阵、action-level metrics 和 verifier 独立性消融，仍可能被判”像已有 runtime defense 的自然组合”。

Path A 策略：
- 已完成的 T64 (live HTTP/local webhook) 和 T65 (headless Chrome DOM/JS) 作为 controlled/protocol evidence 写入主文
- Provider-backed search, SaaS messaging, HTTP browser automation, deployed-agent runtime — 明确写为 **limitation**
- 如果未来获得 API key 或 runtime access，可作为续篇 (future work) 补上

## 6. Reviewer-facing target after this phase

若 T66-T73 完成，论文可以从当前的 “Borderline / Major Revision controlled study” 推进到更强版本：

- novelty 更清晰：不是 benchmark breadth，也不是 generic runtime defense；
- method 更可复现：EffectVerif-AuthMonitor 有接口和伪代码；
- evaluation 更贴近 agent safety：增加 action-level allow/deny metrics；
- validity 更强：label-hidden/minimal-evidence ablation 降低 trace-label leakage 风险；
- claims 更稳：contrastive projection 降级，T64 只作为 live/protocol evidence。

若 T68/T69/T70 任一失败，失败本身也应进入论文限制：

- action-level 指标若弱于 candidate-effect 指标，说明 row-level result 不能直接外推到 deployed monitor；
- minimal-evidence trace 若退化，说明当前 verifier 依赖 structured trace fields；
- conceptual ablation 若无法区分已有 defense，则论文应进一步降为 evaluation/diagnostic paper，而不是 framework method paper。
