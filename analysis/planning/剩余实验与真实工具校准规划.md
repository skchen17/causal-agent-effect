# 剩余实验与真实工具校准规划

> 日期：2026-05-14  
> 用途：给后续 AI 编程工具的实现说明。本文档不要求立即写代码，但应足够具体，使实现者可以按脚本、输入、输出和验收标准推进。  
> 当前环境建议：实验运行使用 conda 环境 `causal-safety`。涉及联网或真实工具执行时必须显式隔离，默认不要执行真实外部副作用。

---

## 0. 总目标

剩余任务分为两条线：

1. **论文主线补强**：完成 causal-chain conditioning、contrastive 多 seed、理论降噪、文献核验。
2. **真实工具流程校准**：核对 `real-agent-tools/` 中真实 agent 工具注册与调用流程，判断当前合成实验是否真实反映真实工具调用，并构造更贴近真实调用链的数据与评估。

当前结论应保持审慎：

> 现有实验能作为“受控语义场景下的工具/表面形式碎片化诊断”，但还不能声称完整覆盖真实 agent 工具调用流程。真实系统中存在 schema 过滤、toolset 可用性、参数强制转换、权限/安全检查、pre/post hook、结果截断、间接工具调用等机制，当前 `scenario_text + tool_name + effects` 数据没有显式建模。

## 1. 当前实验与真实工具的关键差距

### 1.1 当前实验数据格式

当前主要数据文件 `data/scenarios_merged.jsonl` 每行大致为：

```json
{
  "tool_name": "terminal",
  "scenario_text": "自然语言描述...",
  "context_type": "safe|unsafe|prod",
  "effects": {
    "command_executed": 0,
    "file_written": 0,
    "file_deleted": 0,
    "file_content_read": 0,
    "message_sent": 0,
    "network_egress": 0,
    "subagent_spawned": 0,
    "content_fetched": 0,
    "search_performed": 0,
    "memory_updated": 0,
    "tool_error": 0
  }
}
```

现有 embedding 脚本默认只编码 `scenario_text`，下游实验以 `tool_name` 分组、以 `effects` 为多标签目标。

### 1.2 真实 Hermes 工具流程

`real-agent-tools/hermes-agent-tools` 的真实流程是：

1. 每个工具模块通过 `registry.register(...)` 自注册 schema、handler、toolset、check_fn。
2. `model_tools.get_tool_definitions(...)` 根据 enabled/disabled toolsets 解析真实可用工具。
3. registry 会执行 `check_fn`，不可用工具不会暴露给模型。
4. `execute_code` 的 schema 会根据当前 session 实际可用工具动态重写。
5. `handle_function_call(...)` 会做参数类型 coercion。
6. 调用前可能触发 `pre_tool_call` hook 并阻断。
7. 调用 handler 执行真实逻辑。
8. 调用后触发 `post_tool_call` 和 `transform_tool_result` hook。

这意味着真实工具调用不是一个简单的 `tool_name` 标签，而是至少包括：

- `registered_tool_name`
- `toolset`
- `schema`
- `arguments`
- `availability/check_fn`
- `pre_tool_call` decision
- `handler`
- `result/error`
- `post_tool_call` / result transform
- session/task 环境，例如 cwd、sandbox、enabled tools

### 1.3 当前工具名与真实工具名不完全一致

| 当前实验工具名 | Hermes 真实对应 | 主要差距 |
|---|---|---|
| `terminal` | `terminal` | 真实 schema 有 `background`, `timeout`, `workdir`, `pty`, `notify_on_complete`, `watch_patterns`；还有危险命令 approval、sudo、sandbox/env、foreground/background 行为。 |
| `read_file` | `read_file` | 真实 read 有 line pagination、敏感路径检查、device path block、dedup、large-file guard、task cwd resolution。 |
| `write_file` | `write_file`, `patch` | 真实写入会整体覆盖、自动父目录、语法检查、敏感系统路径拒绝；局部编辑应走 `patch`。 |
| `delete_file` | 无直接 Hermes 注册工具；通常经 `terminal` 执行 `rm`, `find -delete`, `shred` 等 | 当前 `delete_file` 是抽象工具，不是 Hermes 真实工具名。真实删除应作为 `terminal` 的一种效果或单独抽象层映射。 |
| `web_fetch` | `web_extract` | Hermes 使用 `web_extract(urls=[...])`；还有 backend、URL safety、website policy、LLM summarization、size cap、PDF handling。 |
| `web_search` | `web_search` | 真实有 backend availability、limit、可能 rate limit/error。 |
| `send_message` | `send_message` | 真实调用有 `action=list/send`、target 解析、平台适配、媒体附件、网关可用性。 |
| `delegate` | `delegate_task` | 真实 schema 是 `goal/context/toolsets/tasks/role/acp_command...`，有并发、递归深度、工具继承、子 agent 隔离。 |
| `memory` | `memory` | 真实 schema 有 `action=add/replace/remove`, `target=user/memory`, `content/old_text`；并非简单“memory updated”。 |
| 无 | `execute_code` | 真实系统支持代码内间接调用 `web_search/read_file/write_file/search_files/patch/terminal`，最多 50 次工具调用；当前实验完全未建模。 |
| 无 | `patch`, `search_files`, `process`, `browser_*`, `todo`, `session_search`, `clarify` 等 | 当前实验只覆盖一小部分工具族。 |

### 1.4 对论文主张的影响

当前实验可以支持：

- 同一因果效果可由不同表面形式产生。
- 模型表征可能按工具/表面形式碎片化。
- 覆盖缺失时，效果探针可能在 heldout form 上漏检。

当前实验不能直接支持：

- 真实 agent 工具调用全流程已经被覆盖。
- 当前效果标签完全等价于真实工具执行后的 ground-truth effects。
- `delete_file`、`web_fetch` 等抽象工具名与真实系统工具一一对应。
- 真实安全策略、approval hook、path guard、toolset availability 对风险的影响已经被测量。

因此后续需要加入 **real-tool fidelity audit**，把“受控合成诊断”升级为“真实工具流程校准后的诊断”。

## 3. P2：Causal-Chain Conditioning 机制实验

### 3.1 研究问题

因果链信息是否改变 LLM 对工具调用的表征组织方式？

需要比较：

- 原始工具调用描述。
- 只强调工具/参数的描述。
- 显式给出动作造成的 causal effects。
- 显式给出任务目标、授权范围、动作效果之间的关系。
- 给出错误或打乱的 causal chain，测试模型是否盲信显式链。

### 3.2 建议新增脚本 4：构造 causal-chain 条件数据

文件名建议：

```text
build_causal_chain_conditioning_data.py
```

输入优先级：

1. 若已完成真实工具样本：使用 `data/real_tool_scenarios.jsonl`。
2. 否则先使用 `data/scenarios_merged.jsonl` 做 pilot。

输出：

```text
data/causal_chain_conditioning.jsonl
analysis/causal_chain_conditioning_manifest.json
```

每个原始样本扩展为 5 个 condition：

| condition | 文本内容 |
|---|---|
| `raw` | 原始 `scenario_text`。 |
| `tool_only` | 只描述工具名、真实工具名、参数，不写效果链。 |
| `effect_chain` | 写出 `tool call -> immediate operation -> causal effects`。 |
| `task_causal_chain` | 写出 `task goal -> authorized effects -> proposed tool call -> actual effects -> consistency/violation`。 |
| `wrong_chain` | 保持工具调用不变，但打乱或篡改 effects。 |

建议每行字段：

```json
{
  "id": "chain-000001",
  "base_id": "real-000001",
  "condition": "task_causal_chain",
  "tool_name": "web_extract",
  "abstract_tool_name": "web_fetch",
  "scenario_text": "Task goal: ... Authorized effects: ... Proposed call: ... Actual effects: ...",
  "effects": {"content_fetched": 1, "network_egress": 1},
  "wrong_chain_target": null,
  "chain_valid": true
}
```

Wrong-chain 构造规则：

- `wrong_chain` 不能随机乱写到不可读；要是“看似合理但错误”的链。
- 至少包含三类错误：
  - **effect omission**：隐去真实危险效果，如 `network_egress`。
  - **effect substitution**：把 `file_deleted` 写成 `file_content_read`。
  - **authorization flip**：把未授权效果写成授权效果。
- 保留 `effects` 为真实标签，另加 `stated_effects` 表示文本中声明的错误标签。

验收标准：

- 4 个首批效果：`content_fetched`, `file_written`, `network_egress`, `tool_error`。
- 每个效果至少 2 个 surface forms。
- 每个 condition 的样本数相同。
- manifest 报告 effect x condition x tool 的正负样本数。

### 3.3 建议新增脚本 5：评估 causal-chain conditioning

文件名建议：

```text
evaluate_causal_chain_conditioning.py
```

输入：

- `embeddings/embeddings_qwen3-8b_causal_chain_conditioning.npy`
- `embeddings/effects_qwen3-8b_causal_chain_conditioning.npy`
- `embeddings/texts_qwen3-8b_causal_chain_conditioning.jsonl`

实现要求：

- 可复用 `lexical_control_experiment.py` 中的 LOTO 逻辑。
- 按 condition 分组评估：
  - LOTO heldout FNR。
  - Within-FNR。
  - ToolProxyGap。
  - Effect probe F1/AUC。
  - tool discriminator accuracy on `E=1`。
- 对 `wrong_chain` 额外评估：
  - probe 是否跟随 `stated_effects` 而非真实 `effects`。
  - wrong-chain induced error rate。

输出：

```text
analysis/causal_chain_conditioning_qwen3-8b.json
analysis/causal_chain_conditioning_qwen3-8b.md
```

核心表格：

| effect | condition | max Held-FNR | max ToolProxyGap | pIIA-Drop 可选 | tool-discriminator acc | wrong-chain error |
|---|---:|---:|---:|---:|---:|---:|

判定标准：

- 若 `task_causal_chain` 降低 ToolProxyGap，同时 `wrong_chain` 不显著诱导错误：可以作为论文第二方法贡献候选。
- 若 `effect_chain` 有效但 `wrong_chain` 也强烈诱导错误：说明模型对显式链敏感但缺乏验证，需要 verifier。
- 若所有 chain condition 无效：说明碎片化更可能来自表征训练层，P3 contrastive 更重要。

## 4. P3：Contrastive Projection 稳健性补强

### 4.1 目标

把 contrastive projection 从单次运行的 mitigation 变成审稿可接受的稳健结果。

### 4.2 建议修改或新增脚本

建议新脚本：

```text
run_contrastive_multiseed.py
```

不要直接覆盖现有 `solution_contrastive.py` 输出。新脚本应调用或复制其中核心训练函数，但输出多 seed 聚合结果。

输入：

- `embeddings/embeddings_qwen3-8b_scenarios_merged.npy`
- `embeddings/effects_qwen3-8b_scenarios_merged.npy`
- `embeddings/texts_qwen3-8b_scenarios_merged.jsonl`

参数：

- seeds: `[0, 1, 2, 3, 4]`，至少 5 个。
- dims: `[64, 128, 256, 512, 1024]`。
- default full-training dim: `128`。
- train epochs/batch/lr 与当前 `solution_contrastive.py` 保持一致，除非另有说明。

输出：

```text
analysis/contrastive_multiseed_qwen3-8b_scenarios_merged.json
analysis/contrastive_multiseed_qwen3-8b_scenarios_merged.md
```

JSON 建议：

```json
{
  "config": {"seeds": [0,1,2,3,4], "dims": [64,128,256,512,1024]},
  "full_training": {
    "file_written": {
      "write_file": {
        "pre_fnr": 0.9697,
        "post_fnr_mean": 0.01,
        "post_fnr_std": 0.02,
        "post_fnr_values": [0,0,0.03,0,0]
      }
    }
  },
  "dim_ablation": {},
  "strict_cross_tool": {}
}
```

### 4.3 strict leave-one-pair-out 重新拆分

必须分两类报告：

1. **Two-form effects**：只有两个 surface forms，例如 `content_fetched` 若只有 `terminal/web_extract`，leave-one-pair-out 后没有剩余跨工具 pair 可训练。不能把它和可传递设置混在一起。
2. **Three-plus-form effects**：例如 `network_egress` 有多个工具，可以测试 transitive alignment。

输出表：

| effect | n_forms | strict setting | pair held out | pre max FNR | post mean FNR | post std |
|---|---:|---|---|---:|---:|---:|

验收标准：

- 主文 contrastive 表能报告均值和方差。
- 不再把 two-form impossible strict 与 three-plus transitive strict 混合。
- `content_fetched` 残余 FNR 除了 N+ 解释，还要给 Wilson CI 或 seed 方差。

## 5. P4：理论与形式化降噪

### 5.1 目标

把理论从“多个定义散列”整理为 causal task consistency 主线。

### 5.2 建议文档修改范围

主要文件：

```text
paper/main.tex
analysis/formalization.md
analysis/contrastive_theory.md
```

新增或整理的概念：

```text
Task τ
Authorized effect envelope A(τ)
Tool call c = (tool, args)
Observed/predicted effect set Ω(c)
Causal task consistency: Ω(c) ⊆ A(τ)
Representation-level consistency: same effect across surface forms should support invariant detection
```

必须保持：

- Theorem 1 是 FNR-to-unsafe-allow risk accounting，不是完整安全证明。
- Theorem 2 是 coverage sample complexity。
- Theorem 3-4 是 contrastive 的 conditional analysis，依赖 margin、linear separability、bounded alignment error。
- pIIA 是 diagnostic，不进入安全定理前提。

验收标准：

- 主文中不会出现 `pIIA -> safety proof` 的强链条。
- 不把 synthetic controlled study 写成真实 agent 全覆盖结论。
- real-tool fidelity audit 结果出来前，真实工具相关表述必须写成“calibration / external validity check”。

## 9. 安全与实现约束

- 不要默认执行真实 `terminal`, `send_message`, `web_extract`, `delegate_task`, `memory`。
- 真实工具流程校准优先用静态 schema 和 dry-run 模拟。
- 若必须运行真实工具，只允许在专门 sandbox 中运行 allowlisted harmless calls，例如：
  - `terminal: pwd`, `whoami`, `echo test`
  - `read_file` 读取项目内小文件
  - 禁止真实 `rm`, `write_file` 覆盖重要文件, `send_message`, 真实外网请求
- 所有新增实验必须输出 manifest，记录样本数、effect/tool 分布和生成规则。
