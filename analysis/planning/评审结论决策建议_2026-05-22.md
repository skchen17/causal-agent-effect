# 评审结论决策建议：Borderline Reject 后的主线收敛

> 日期：2026-05-22  
> 输入：用户提供的新一轮总体评审结论  
> 目标：判断是否继续当前稿件、如何重构主贡献、是否引入新方法。

## 1. 决策结论

建议 **不按当前形态继续投稿主会**。当前稿件最稳结论是 `Weak Reject / Borderline Reject`，原因不是研究方向不成立，而是主贡献过宽、外部有效性不足、结构化 trace 依赖过强、action-level policy 未闭合。

主会目标仍可保留，但下一轮应从“多组件综合论文”转为 **一篇聚焦的 Auth-SafeInv 方法/评估论文**：

> 核心问题：agent monitor 应基于真实执行证据判断 realized effects 是否被任务授权。  
> 核心失败：工具表面形式和结构化 trace shortcut 会让 row-level 指标看起来很好，但 action-level safety/utility 不闭合。  
> 核心方法：从 label-hidden/minimal raw traces 中构造可校准的 realized-effect evidence，再做 action-level selective authorization。

## 3. 推荐主线重构

### 3.1 主论文只保留一个主张

建议把主张改成：

> Authorization-conditioned realized-effect monitoring is a necessary evaluation target for LLM agents. Existing surface-form and trace shortcuts can make monitor evaluation over-optimistic; robust evaluation must test held-out tool surfaces, label-hidden execution evidence, and action-level allow/deny tradeoffs.

中文：

> Agent 安全监控的核心评估对象应是“实际产生的效果是否被任务授权”。仅看工具名、schema、结构化标签字段或 candidate-effect row 级 FNR/FPR 都会高估安全性；主会版本必须以 held-out tool、label-hidden trace 和 action-level policy 为核心评估。

### 3.2 主文结构建议

1. Problem: authorization-conditioned realized-effect consistency.
2. Diagnostic: surface-form fragmentation causes held-out unauthorized-effect misses.
3. Negative result: strict pure representation repair is insufficient.
4. Method: label-hidden/minimal-evidence EffectVerif + selective AuthMonitor.
5. Main metrics: action-level U-Allow and FDeny, with row-level FNR/FPR as decomposition.
6. External validity and limits: controlled/protocol evidence unless provider-backed traces are added.

pIIA、contrastive projection、causal-chain conditioning、理论 alignment bound 全部降级到 appendix/supporting diagnostics。

## 4. 新方法建议：CEG-Auth

建议新增一个明确方法，暂名 **CEG-Auth: Causal Evidence Graph Authorization Monitor**。

关键修正：**graph 本身不是贡献**。OpenTelemetry、W3C PROV、AgentArmor、ARGUS 等已经说明 graph/provenance/runtime trace abstraction 是自然且已有的安全表示方式。CEG-Auth 的新意必须落在特定问题设定和决策机制上：

- authorization-conditioned realized-effect inference；
- label-hidden raw trace input；
- effect probability + localized evidence subgraph + uncertainty；
- action-level selective policy over `A(c)` violations。

### 4.1 方法动机

当前 EffectVerif-AuthMonitor 最大弱点是：full-label trace 可能包含接近答案的结构化字段，minimal-evidence 又明显退化；同时 action-level policy 会过度拒绝或 all-allow collapse。

CEG-Auth 直接针对这两个失败：

- 用 label-hidden raw evidence 构造 typed causal evidence graph，避免依赖 `verified_effects` / `unauthorized_effects` 等标签字段；但不把“构图”本身写成 novelty。
- 用 selective action policy 处理 uncertainty，而不是把任一 candidate-effect 高分直接转成 DENY。

### 4.2 方法接口

输入：

- task context `c`
- authorized envelope `A(c)`
- tool call `(a,S,x)`
- raw execution trace `t_raw`

步骤：

1. `EventExtract(t_raw) -> G_t`  
   从 raw trace 中抽取低层事件图，例如 file diff、process exit、stdout/stderr、HTTP request/response、DOM mutation、localStorage change、message receipt。

2. `EffectInfer(G_t, e) -> (p_e, evidence_e, u_e)`  
   对每个候选 effect 输出概率、证据片段和不确定性。训练和评估时禁止输入显式 effect labels、verified effects、unauthorized effects、policy labels。

3. `AuthCompare(A(c), {p_e}) -> risk_U`  
   只对 `e notin A(c)` 的 realized-effect probability 聚合 unauthorized risk。

4. `SelectivePolicy(risk_U, utility_cost) -> ALLOW / DENY / ABSTAIN`  
   用 validation 或 conformal calibration 控制 action-level U-Allow / FDeny tradeoff。高不确定性 action 不强行二分类，而是 ABSTAIN、ask user、sandbox rerun 或 require stronger verifier。

### 4.3 训练与评估要求

主结果必须使用：

- label-hidden raw trace；
- minimal-evidence trace；
- held-out tool family；
- held-out trace family；
- action-level U-Allow / FDeny；
- exact binomial CI 和 bootstrap CI。

禁止作为主结果：

- full-label trace verifier；
- oracle `candidate_effect_present`；
- full-training contrastive projection；
- row-level 0/0 FNR/FPR 单独作为安全 claim。

### 4.4 预期可证伪结果

CEG-Auth 如果成立，应满足：

- 在 label-hidden/minimal-evidence trace 上，U-Allow 显著低于 pre-action/provenance-only baselines。
- FDeny 不应在 T61/T65 继续等于 1.0。
- 在 strict held-out tool family 上，性能不应完全依赖已见 tool-surface。
- all-allow threshold 不应成为满足 false-denial constraint 的唯一选择。

如果做不到，应承认当前论文只能作为 evaluation/diagnostic paper，而不能作为方法论文。

### 4.5 必须比较的 graph novelty boundary

主文必须明确：

- AgentArmor: agent runtime trace -> program-dependence style graph IR -> type-system policy enforcement。
- ARGUS: influence provenance graph -> trusted/untrusted context influence auditing before execution。
- CEG-Auth: label-hidden raw execution evidence -> realized-effect probability/evidence/uncertainty -> authorization-conditioned selective action decision。

因此本文不能声称“首次用 graph 做 agent security”，只能声称在 Auth-SafeInv 问题设定下，图用于 label-hidden realized-effect inference 和 action-level selective authorization。
