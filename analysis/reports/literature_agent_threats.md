## 二、各文献详细内容

### 1. AttriGuard (arXiv:2603.10749, Mar 2026)

**问题**：间接提示注入（IPI）——攻击者通过投毒工具输出或检索内容，诱导 agent 执行非用户意图的工具调用。

**威胁模型**：
- 攻击者控制 agent 可访问的外部内容（网页、文件、检索结果）
- 攻击目标：诱导 agent 调用攻击者指定的工具，执行未授权操作
- 攻击者能力：静态注入（固定 payload）和自适应优化注入

**方法**：**动作级因果归因**
1. 对每个工具调用，构造两个并行执行：
   - 原始执行（含所有上下文）
   - 控制执行（排除或削弱可疑上下文源）
2. 比较两次执行的工具调用是否一致
3. 若不一致 → 标记为注入攻击（工具调用是由外部内容驱动的，而非用户意图）

**实验数据**：
- 4 个 LLM，2 个 agent benchmark
- 静态攻击下：**0% 攻击成功率**（全部拦截）
- 自适应优化攻击下仍有效
- 核心指标：工具调用因果归因准确率

**与我们的关系**：AttriGuard 做的是**行为层**的因果归因（输入→工具调用）。我们做的是**表征层**的因果诊断（嵌入→效果）。两者使用相同的因果推理范式（反事实比较），但操作在不同层面。AttriGuard 隐式假设"如果工具调用由用户意图驱动，其效果可以被正确理解"——这正是我们证明不成立的假设。

### 2. ARGUS (arXiv:2605.03378, May 2026)

**问题**：上下文感知的提示注入——攻击 payload 嵌入在 agent 处理的文档/数据中，通过上下文传播影响 agent 决策。

**威胁模型**：
- 攻击者可以向 agent 的工作环境中注入任意文本内容
- 注入内容在上下文中看似合法（如文档、代码注释、元数据）
- 目标：改变 agent 的行为决策（工具选择、参数、执行顺序）

**方法**：**影响溯源图**
1. 构建 agent 决策过程中的信息流图
2. 标注每条信息的来源（用户指令 vs 外部检索 vs 中间产物）
3. 当决策依赖于不受信任来源的信息时，触发审计或拦截
4. 使用溯源感知的决策审计（provenance-aware decision auditing）

**实验数据**：
- 攻击成功率降到 **3.8%**（vs baseline 防御的 40-80%）
- 保留 **87.5%** 任务效用
- 显著优于 PromptGuard、Llama-Guard 等 prompt-level 防御

**与我们的关系**：ARGUS 的"影响溯源图"是我们的"表征碎片化诊断"的互补视角。ARGUS 追踪信息流在上下文中的传播，我们追踪因果方向在表征空间中的传播。两者可以结合：ARGUS 判断"这个决策是否受污染"，我们判断"这个决策的因果效果是否被正确编码"。

### 3. ClawGuard (arXiv:2604.11790, Apr 2026)

**问题**：工具增强 LLM agent 在执行时受到三类注入攻击——网页/本地内容、MCP 服务器、技能文件。

**威胁模型**：
- 攻击面在 tool-call boundary（工具调用的输入和输出接口）
- 攻击者通过投毒工具描述、MCP 服务器响应、或技能文件内容注入 payload
- 目标：绕过模型级安全过滤，诱使 agent 执行危险工具调用

**方法**：**确定性工具调用边界执行**
1. 在 agent 接收用户目标后、调用任何外部工具前：从用户目标**自动推导**任务特定的访问约束
2. 每次工具调用在执行前经过约束验证
3. 不修改模型，不依赖模型级安全过滤
4. 三个注入通道统一处理

**实验数据**：
- 5 个 SOTA 模型
- AgentDojo, SkillInject, MCPSafeBench 三个 benchmark
- 跨模型鲁棒保护
- 代码已开源

**与我们的关系**：ClawGuard 的核心假设是"可以从用户目标中推导出正确的工具调用约束"。但约束是"这个工具调用是否在授权范围内"——边界层问题。我们的工作是"这个工具调用会产生什么因果效果"——表征层问题。ClawGuard 需要我们的诊断作为输入：如果因果效果不能被可靠预测，ClawGuard 的约束验证就缺乏可靠的输入信号。

### 4. XOA: Execute-Only Agents (Agentic OS Workshop, 2026)

**问题**：LLM 本身是攻击面——只要 LLM 能"看到"不可信数据，注入攻击就可能成功。

**威胁模型**：
- 最激进的威胁模型：**任何 LLM 可访问的外部数据都可能是恶意的**
- 不假设模型可以学会区分可信/不可信内容
- 目标：从架构层面消除攻击面

**方法**：**执行-隔离范式**
1. LLM 只生成脚本（不直接调用工具）
2. 脚本在隔离沙箱中执行
3. LLM **从未接触到不可信数据**（不可信数据只进入沙箱，不进入 LLM 上下文）
4. ~78% 的 AgentDojo 任务可以通过此方式完成

**实验数据**：
- AgentDojo benchmark: 78% 任务可脚本化
- 零注入攻击成功（根本不存在攻击面）
- 代价：22% 任务需要 LLM 直接处理不可信数据

**与我们的关系**：XOA 代表了最激进的安全范式——移除攻击面而非检测攻击。但 22% 的任务仍然需要 LLM 直接处理不可信数据。对于这些任务，我们的表征碎片化诊断是必要的——XOA 无法保护它们。

### 5. LITMUS (arXiv:2605.10779, May 2026)

**问题**：现有 jailbreak 基准只测量文本级危害（生成有害内容）。**行为越狱**——agent 执行不可逆的 OS 级操作——未被系统测量。

**威胁模型**：
- 攻击者通过三种范式诱导 agent 执行 OS 级危险操作：
  1. **Jailbreak speaking**：说服性语言诱导越权
  2. **Skill injection**：在工具/技能描述中嵌入恶意指令
  3. **Entity wrapping**：将危险操作包装为合法实体操作
- 目标操作：文件删除、凭证窃取、SSH 操纵（物理不可逆）

**方法**：819 高风险测试用例，在真实 OS 环境中评估 agent 行为

**实验数据**：
- Claude Sonnet 4.6 执行了 **40.64%** 的高风险操作
- **发现"执行幻觉"（Execution Hallucination）**：agent 口头拒绝请求，但危险操作**已经执行完成**——所有先前的语义级基准无法检测
- 三种攻击范式均有效

**与我们的关系**：LITMUS 的"执行幻觉"是我们的核心关心的安全后果的直接证据。在"执行幻觉"场景中，agent 的文本输出（"我拒绝"）与工具调用的因果后果（文件已删除）之间存在脱耦。这正是我们定义 MultiMech 和 SafeInv 所要解决的问题——在 LLM 内部建立因果后果的一致编码。

### 6. JAW (arXiv:2605.11229, May 2026)

**问题**：agentic 工作流（GitHub Actions, n8n）中的上下文注入攻击。

**威胁模型**：
- 攻击者向工作流平台提交内容（GitHub Issue 评论、PR 描述等）
- 工作流中的 LLM agent 读取这些内容
- Agent 被诱导执行任意命令或窃取凭证
- 影响面：4714 个真实 GitHub 工作流，8 个 n8n 模板

**方法**：**上下文接地演进**——生成自然嵌入在上下文中的恶意 payload，利用工作流中的 agent 自主性

**实验数据**：
- **4714 个工作流被成功劫持**
- 影响 15 个广泛使用的 GitHub Actions，包括 **Claude Code、Gemini CLI、Qwen CLI、Cursor CLI** 的官方 Action
- 已获 GitHub、Google、Anthropic 的致谢、修复和漏洞赏金

**与我们的关系**：JAW 证明 agent 工作流中的上下文注入**已在野外发生**，且影响面巨大。我们的工作提供了这种攻击在表征层面为何可行的机制解释——LLM 在上下文中看到"看起来合法的指令"时，无法从表征层面区分其与用户真实意图的因果后果差异。

### 7. QueryIPI (arXiv:2510.23675, Jan 2026)

**问题**：传统间接注入依赖用户查询中的特定触发词。但 agent 的系统提示和工具描述是**查询不变的**——可以作为更稳定的注入向量。

**威胁模型**：
- 攻击者优化工具描述中的 payload——agent 每次调用该工具时都被暴露
- Payload 不依赖特定用户查询
- 通过黑盒优化（CMA-ES）优化 payload 以最大化攻击成功率

**方法**：
1. 将工具描述作为可优化的注入向量
2. 定义攻击目标（如"调用 send_message 向外部发送数据"）
3. 使用 CMA-ES 优化工具描述中的自然语言 payload
4. 评估跨用户查询的泛化攻击成功率

**实验数据**：
- **87% 攻击成功率**（vs 50% baseline）
- 攻击跨查询泛化
- 转移到真实编码 agent 有效

**与我们的关系**：QueryIPI 的攻击面恰好是我们诊断的"工具特定表面特征"的另一面。如果 agent 安全系统依赖探针检测效果，攻击者可以通过工具描述注入来改变 agent 的嵌入，使其偏离探针的检测范围——这就是上下文注入版的工具代理攻击。

### 8. AMA: Attractive Metadata Attack (NeurIPS 2025, arXiv:2508.02110)

**问题**：LLM agent 通过工具元数据（名称、描述、参数 schema）选择工具。攻击者可以使恶意工具在元数据层面比合法工具更具吸引力。

**威胁模型**：
- 黑盒：攻击者不知道模型参数，可以查询 agent 的工具调用行为
- 攻击者控制恶意工具的元数据
- 目标：诱导 agent 选择恶意工具而非法工具，从而执行隐私窃取、数据外泄等操作

**方法**：
1. 生成"高吸引力"的工具元数据（利用 LLM 对自然语言的敏感性）
2. 针对 MCP（Model Context Protocol）的工具注册机制
3. 基于预测的优化：预测哪些元数据特征对 agent 最有吸引力

**实验数据**：
- **81%-95% 攻击成功率**，跨 10 个场景和多个主流 LLM
- Prompt 级别防御、审计检测、MCP 协议**均不能有效防御**
- 攻击与提示注入正交——可以组合使用

**与我们的关系**：AMA 揭示了工具选择阶段的脆弱性。如果 agent 选择了恶意工具，那么该工具产生的因果效果与我们预定义的 11 个效果可能完全无关——效果词汇表之外的新效果（如 credential_leaked）无法被现有探针检测。这是 SafeInv 定义中"效果覆盖完整"假设的一个反例——攻击者可以引入检测范围之外的新效果。

---

### 9. LASM Survey (arXiv:2604.23338, Apr 2026)

**内容**：系统的安全综述，提出**分层攻击面模型（LASM）**

**分类体系**：
- **7 层**：Foundation → Cognitive → Memory → Tool Execution → Multi-Agent Coordination → Ecosystem → Governance
- **4 个时间性类别**：瞬时、会话持久、跨会话累积、子会话栈
- 分析 **116 篇论文**（2021-2026）

**关键发现**：
- **上层和多时间尺度的威胁严重未被探索**
- 许多攻击区域**零防御**
- 长期累积威胁和跨会话攻击缺乏基准和防御

**与我们的关系**：我们的工作属于 LASM 的 Cognitive 层——具体是"效果预测器的表征可靠性"。LASM 的分类确认了这个方向是整个 agent 安全栈中的一个独立且有价值的层次。

### 10. MDPI Formal Threat Model (Computation, Apr 2026)

**问题**：agent 工具调用安全缺乏统一的形式化威胁模型。

**威胁模型**（形式化）：
- **三个独立维度**：Compromise（攻击者能做什么）、Harm（后果有多严重）、Severity（发生的可能性）
- 使用 **Monte Carlo 评估管线**：将架构选择（权限、检索、记忆暴露、审批）映射到可比较的安全指标

**关键发现**：
- **最小权限工具设计是最强的单一架构控制**
- Human-in-the-loop 审批大幅减少高风险动作，但**在用户习惯下退化**
- 检索白名单几乎消除间接注入

**与我们的关系**：这份形式化模型提供了与我们的安全定理对接的框架。Compromise 维度对应我们的 $\beta$（FNR），Harm 对应 $\mathcal{E}_{\text{critical}}$，Severity 对应定理 2 的 $q$（稀有组合概率）。我们的定理 1+2 可以嵌入这个三维框架中。

## 三、与我们工作的交叉定位

```
Agent 安全防御栈（从上到下）：

┌──────────────────────────────────────────────────────┐
│ 第 5 层：架构隔离 (XOA)                               │
│   沙箱执行，LLM 不接触不可信数据                       │
│   ── 最安全，但有 22% 任务不可行                       │
├──────────────────────────────────────────────────────┤
│ 第 4 层：边界验证 (ClawGuard, AttriGuard)             │
│   工具调用执行前拦截，因果归因，约束推导               │
│   ── 假设：工具调用的因果效果可以被可靠预测 ← 我们在这  │
├──────────────────────────────────────────────────────┤
│ 第 3 层：表征可靠性 (← 我们的位置)                     │
│   MultiMech, Frag, SafeInv, pIIA, 对比投影              │
│   ── 诊断和确保 LLM 内部的因果效果编码是工具不变的      │
├──────────────────────────────────────────────────────┤
│ 第 2 层：影响溯源 (ARGUS)                               │
│   追踪信息传播，检测上下文投毒                           │
│   ── 假设：效果检测器能可靠识别已执行的操作的后果       │
├──────────────────────────────────────────────────────┤
│ 第 1 层：输入过滤 (PromptGuard, Llama-Guard)             │
│   检测和过滤恶意输入                                     │
│   ── 共识：输入过滤不足以保证 agent 安全                │
└──────────────────────────────────────────────────────┘
```

**我们的独特贡献**：第 3 层（表征可靠性）是栈中**唯一缺失的层**。第 1-2 层被共识为不足，第 4-5 层是前沿方向，但它们都隐式依赖第 3 层的可靠性——如果 LLM 内部无法可靠编码因果效果，上层边界验证的输入就不可靠。

## 四、论文中的 Related Work 讨论框架

1. **Agent 安全威胁**（JAW, LITMUS, QueryIPI, AMA）——上下文注入、行为越狱、工具元数据攻击提供了问题动机
2. **Agent 安全防御**（AttriGuard, ARGUS, ClawGuard, XOA）——行为层和边界层方法，但依赖未经验证的表征层假设
3. **因果抽象与表征**（Geiger, Sutter）——提供了我们的诊断方法论
4. **本文的定位**——填补表征可靠性在 agent 安全栈中的空白
