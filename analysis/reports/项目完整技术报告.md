# Agent 安全中因果效果的表征碎片化：诊断、理论与缓解

> 完整技术报告 | 2026-05-18 | 目标会议：NeurIPS/ICML/AAAI

---

## 零、一句话概述

**LLM 按"怎么说"组织信息，不按"做了什么"组织信息。** 同一因果效果（如删除文件）通过不同工具（如 `delete_file` 和 `terminal rm`）产生时，在 LLM 嵌入空间中相距甚远，导致跨工具效果检测不可靠。这是所有现有 agent 安全防御忽视的底层前提。

---

## 一、从什么思想出发

### 1.1 问题的起源：Agent 安全的前提是什么

现有 agent 安全防御（AttriGuard、ClawGuard、ARGUS、XOA）都在"行为层"或"边界层"工作——它们拦截工具调用、追踪信息传播、在沙箱中隔离执行。这些方法都依赖一个共同的前提：

> **给定一个工具调用，安全系统能够可靠判断"这个操作会产生哪些因果后果"。**

如果系统分不清"删除了临时文件"和"删除了关键配置"，或者分不清"获取了公开文档"和"发送了内部数据"——那么整个安全栈的输入就是不可靠的。

### 1.2 核心概念：Causal Task Consistency

我们提出**因果任务一致性（Causal Task Consistency）**作为 agent 安全的基本要求：

$$\Omega(a, S) \subseteq A(c)$$

其中：
- $c$ 是任务上下文（"检查配置文件"）
- $A(c)$ 是授权效果包络（允许 `file_content_read`，不允许 `file_deleted`）
- $\Omega(a, S)$ 是动作 $a$ 经表面形式 $S$ 的实际因果后果
- 安全违规 = $U(c,a,S) = \Omega(a,S) \setminus A(c) \neq \emptyset$（有不被授权的效果发生了）

如果 LLM 自己都不能一致地编码"这个操作产生了什么因果效果"，$U(c,a,S)$ 就无法被可靠检测。

### 1.3 为什么这是一个被忽视的问题

LLM 的预训练目标是**预测下一个 token**——本质上是学习 token 的**共现模式**，而非因果结构。"删除了文件"和"执行了 rm -rf"在预训练语料中很少出现在同一个上下文中（前者出现在 API 文档中，后者出现在 shell 教程中），因此它们的嵌入被拉向不同的方向。

这就是**表面形式碎片化（Surface-Form Fragmentation）**的根因。

## 二、做了什么实验

### 2.1 数据构造

#### 核心设计原则：打破"工具→效果"的确定性捷径

早期模板数据（实验 1，900 条）中，每个工具有固有效果——`memory` 永远产生 `memory_updated=1`。探针只需学会"9 分类工具识别器"就能达到 F1=0.97，是虚假的高分。

**实验 2 的解决方法**：构造**反事实场景**——同一工具在不同上下文中产生不同效果：

| 场景 | 工具 | 效果 |
|------|------|------|
| "agent 执行了 `ls -la`（safe mode）" | terminal | command_executed=1, **network_egress=0** |
| "agent 执行了 `curl https://api.github.com`（unsafe）" | terminal | command_executed=1, **network_egress=1** |
| "agent 执行了 `rm -rf /tmp/cache`（unsafe）" | terminal | command_executed=1, **file_deleted=1** |

同时构造**跨工具等价场景**——同一效果通过不同工具实现：

| 场景 | 工具 | 效果 |
|------|------|------|
| "agent 从 https://api.github.com 获取了 JSON 数据" | web_fetch | content_fetched=1 |
| "agent 执行了 `curl -s https://api.github.com`" | terminal | content_fetched=1 |

#### 生成方式

| 来源 | 数量 | 方法 |
|------|:---:|------|
| 规则模板 | 184 条 | 每个工具 2-6 种场景变体，上下文条件分支 |
| LLM 合成 | 100 条 | DeepSeek V4 Flash 按主题生成 |
| 定向生成 | 175 条 | 针对低频效果（N+ < 50）的定向 LLM 生成 |
| **总计** | **459 条** | |

#### 主会扩展（mainconf v2）：932 条

为解决 N+ < 30 的小样本风险，增加了 408 条增量数据 + 65 条 static replay traces。7 个关键效果-工具对的 N+ 全部达到 ≥ 50。

#### 授权条件扩展（Auth-SafeInv）：1464 条

构造了 4 类 counterfactual families（1184 条 v1 → 1464 条 v2）：

| Family | 说明 | 示例 |
|------|------|------|
| same_task_tool_swap | 同任务、同效果，不同工具 | web_fetch vs terminal curl |
| same_tool_auth_flip | 同工具、同效果，授权状态反转 | "允许写入" vs "只读，不许写" |
| same_effect_reframing | 同效果，不同语义框架 | "删除" vs "清理过期数据" |
| same_task_effect_substitution | 同任务，不同效果 | 读取 vs 读取+网络出站 |

### 2.2 实验 1-2：问题诊断——线性可编码性

#### 原理

**线性探针**：在 LLM 的嵌入 $\mathbf{h} \in \mathbb{R}^d$ 上训练一个逻辑回归分类器来预测因果效果 $E$：

$$\hat{P}(E=1 | \mathbf{h}) = \sigma(\mathbf{w}^\top \mathbf{h} + b)$$

如果 $\mathbf{w}$ 能高精度预测 $E$，说明效果 $E$ 在 LLM 表征中是**线性可编码的**——这对应 Geiger 因果抽象框架中的对齐映射 $\tau$。

**Δ 分析**：同时训练非线性探针（MLP/RBF），计算 $\Delta = \text{F1}_{\text{nonlinear}} - \text{F1}_{\text{linear}}$。

- 如果 $\Delta \approx 0$：效果被线性编码，因果解释可证伪（满足 Sutter et al. 的线性约束要求）
- 如果 $\Delta \gg 0$：效果需要非线性解码，因果解释可能是空洞的

#### 结果

在反事实数据上，线性探针的 F1 从模板数据的 0.97 降到 0.60-0.80（打破捷径），而非线性探针（MLP 128×64, RBF kernel）不能系统性地超越线性探针（Δ ≈ 0）。这表明因果效果以近似线性的方式编码在 LLM 表征中。

### 2.3 实验 3：交叉工具泛化——发现碎片化

#### 原理

**LOTO（Leave-One-Tool-Out）压力测试**：对于一个效果 $E$，训练探针时排除工具 $T$ 的所有数据，然后在 $T$ 上测试。

$$\text{FNR}_{\text{LOTO}}(E, T) = P(\tau_{-T}(\mathbf{h}) \leq 0.5 \mid E=1, T)$$

其中 $\tau_{-T}$ 是在除 $T$ 外所有工具上训练的探针。

**为什么 LOTO 是合理的？** 在真实部署中，agent 可能使用训练数据中从未出现的工具来执行操作。LOTO 模拟了这种"覆盖缺失"场景。

#### 结果（Qwen3-8B, 459 条）

| 效果 | Source Tool | Src-FNR | Heldout Tool | Held-FNR | N+ | 碎片化严重度 |
|------|:---:|:---:|------|:---:|:---:|:---:|
| content_fetched | web_fetch | 0.064 | terminal | **0.500** | 8 | 中等 |
| content_fetched | terminal | 0.111 | web_fetch | **0.781** | 32 | **严重** |
| file_written | terminal | 0.478 | write_file | **0.970** | 33 | **极度严重** |
| file_content_read | terminal | 0.215 | read_file | **0.875** | 32 | **严重** |
| tool_error | terminal | 0.236 | web_search | **0.100** | 10 | 轻微 |

**核心发现**：同效果在源工具内 FNR 很低（0.03-0.48），一旦换到未见过的工具，FNR 飙升至 0.50-0.97。这不是探针容量问题——是表征本身的碎片化。

**词汇控制实验**确认碎片化不是词汇捷径：将工具名替换为 `[TOOL]`、命令替换为 `[CMD]`、URL 替换为 `[URL]` 后，FNR 变化极小（content_fetched terminal 维持在 0.50）。

### 2.4 实验 4：pIIA——因果验证

#### 原理

**pIIA（Probe-Mediated Interchange Intervention Accuracy）** 是 Geiger 互换干预的探针版本。

**操作**：
1. 在 LLM 的第 24 层（共 36 层），提取基准样本 $b$ 和源样本 $s$ 的激活
2. 沿效果探针方向 $\mathbf{w}$ 计算均值投影差异：$\Delta = \hat{\mathbf{w}}\hat{\mathbf{w}}^\top(\bar{\mathbf{h}}_\ell^s - \bar{\mathbf{h}}_\ell^b)$
3. 将 $\Delta$ 注入基准样本的每个 token：$\mathbf{h}_{\ell, r}^{\text{int}} = \mathbf{h}_{\ell, r}^b + \Delta$
4. 让被干预的激活通过模型上层传播到最终层
5. 用**独立工具**的探针评估：干预是否使预测朝正确方向变化？

$$\text{pIIA}(A \to B) = P\left(\tau_B(N_{>\ell}(I_{\mathbf{w}_A}(\mathbf{h}_\ell^b, \mathbf{h}_\ell^s))) > \tau_B(\mathbf{h}_L^b) \mid E(b)=0, E(s)=1, T(b)=T(s)=B\right)$$

**为什么这是因果性的？** 干预方向来自工具 $A$（$\mathbf{w}_A$），评估探针来自工具 $B$（$\tau_B$）。如果 $\mathbf{w}_A$ 真的捕获了效果 $E$ 的因果方向而非工具特定特征，那它在 $B$ 的表征中也应该有效。上层传播进一步测试了"模型是否认可这个方向"——如果上层网络"纠正"了干预，说明方向不是因果的。

#### 结果

| 效果 | pIIA-within | pIIA-cross | pIIA-Drop | 结论 |
|------|:---:|:---:|:---:|:---:|
| tool_error | 1.000 | 0.948 | 0.052 | ✓ 因果概念 |
| file_content_read | 1.000 | 0.837 | 0.164 | ~ 部分错位 |
| content_fetched | 1.000 | 0.702 | 0.298 | ◈ 显著错位 |
| network_egress | 1.000 | 0.634 | 0.366 | ◈ 严重错位 |

**tool_error 为什么特殊？** 不同工具的错误表达共享丰富的跨工具语言学信号："被权限拒绝"、"速率限制"、"命令不存在"、"网络超时"——这些"否定/失败"语义在预训练语料中高频共现，LLM 天然将它们编码到附近区域。

**pIIA 控制** 确认这不是假象：随机方向的 cos≈0、wrong_effect 方向 cos≈0.02-0.32、跨工具方向 cos 0.09-0.35（正相关于 transfer quality）。

### 2.5 实验 5：Baseline 排除

测试了 5 种自然修复方法，无一能系统解决碎片化：

| 方法 | 原理 | 为什么失败 |
|------|------|------|
| Pooled | 所有工具混合训练 + class_weight=balanced | 多数类工具主导决策边界 |
| Balanced Pooled | 每工具等量采样 | 部分改善，但跨工具表征分离不变 |
| Tool-Conditioned | 嵌入拼接工具 one-hot ID | LOTO 下 heldout 工具 ID 退化为全零 |
| Group Reweight | 逆频率 per-tool 权重 | 稀有工具 upweight 引入噪声方向 |
| Procrustes Align | 旋转 $\mathbf{w}_A$ 到 $\mathbf{w}_B$ | 碎片化不在方向角度中，在方差/协方差中 |

---

### 2.6 实验 6：对比投影——解法

#### 原理

在原始 4096 维空间中，`web_fetch` 的 content_fetched 正样本和 `terminal` 的 content_fetched 正样本分布在两个分离的子流形上。不存在单一的线性超平面（1D 方向）能同时高精度分离两者。

**对比投影**学习一个线性投影矩阵 $P \in \mathbb{R}^{d \times k}$（$k=64$），将嵌入映射到低维空间：

$$\mathbf{z} = \frac{P^\top \mathbf{h}}{\|P^\top \mathbf{h}\|}$$

**损失函数**：

$$\mathcal{L}(P) = \underbrace{\frac{1}{N}\sum_{(a,b)}\|\mathbf{z}_a - \mathbf{z}_b\|^2}_{\text{拉近同效果、不同工具}} + \underbrace{\lambda\cdot\frac{1}{N}\sum_{(a,b)}\max(0, m - \|\mathbf{z}_a - \mathbf{z}_{\text{neg}}\|)^2}_{\text{推开不同效果的样本}} + \gamma\|P\|_F^2$$

**为什么投影到低维有效？** 64 维相比于 4096 维是一个信息瓶颈。这个瓶颈强制 $P$ 丢弃工具特定的表面特征（如 "fetch" vs "curl" 的语法模式），只保留跨工具的因果语义（"获取了内容"）。

#### 结果

| 指标 | 值 |
|------|:---:|
| 全量训练改善 | 16/20 效果-工具对, ΔFNR=+0.37 |
| Strict LOPO（只保留一对 heldout 工具的对比对） | 40/68 改善, Δ=+0.157 |
| 维度鲁棒性 | 64-1024 全有效, 64 最优（更小瓶颈 → 更强丢弃） |
| content_fetched 残余 FNR | 0.22（仅 8 个 terminal 正样本 → 8 个对比对） |

#### 理论保证

**定理 3（对比泛化界）**：以概率 ≥ 1-δ，对比投影的泛化误差满足

$$\mathcal{L}(\hat{P}_N) - \mathcal{L}(P^*) \leq O\left(B^2R\sqrt{\frac{dk}{N}}\right)$$

推论：为达到对齐精度 $\varepsilon$ 需要 $N = \Omega(dk/\varepsilon^2)$ 个对比对。

**定理 4（对齐 → FNR 降低）**：若投影空间中正负类被 margin $\rho_A$ 分开，且对齐误差 $\varepsilon_{\text{align}} \leq \rho_A/2$，则：

$$\text{FNR}_B(\tau_A) \leq \text{FNR}_A(\tau_A) + \frac{2\varepsilon_{\text{align}}}{\rho_A}$$

**这意味着**：对比损失优化减小 $\varepsilon_{\text{align}}$（拉近跨工具正样本），同时增大 $\rho_A$（推开正负类），协同降低跨工具假阴性率。

### 2.7 实验 7：因果链条件——输入侧缓解

#### 原理

除了在表征侧做对比投影，是否可以在输入侧提供因果链信息来帮助 LLM 建立跨工具关联？

**5 种条件**：

| 条件 | 文本内容 |
|------|------|
| raw | 原始场景描述 |
| tool_only | 仅工具名和参数 |
| effect_chain | "tool → immediate operation → causal effects" |
| task_causal_chain | "task goal → authorized effects → proposed call → actual effects → consistency" |
| wrong_chain | 提供错误/篡改的效果声明 |

#### 结果

| 效果 | raw Held-FNR | task_causal_chain Held-FNR | 改善 |
|------|:---:|:---:|:---:|
| content_fetched | 0.78 | **0.00** | 消除 ✓ |
| network_egress | 0.69 | **0.00** | 消除 ✓ |
| tool_error | 0.27 | **0.00** | 消除 ✓ |
| file_written | 0.97 | **0.71** | 部分 |

**发现**：显式因果链信息可以大幅改善检测，但效果不均匀。wrong_chain 诱导 12-24% 的决策错误，说明 LLM 对显式链敏感但缺乏验证能力。

### 2.8 实验 8：授权条件安全评估（Auth-SafeInv）

#### 原理

在授权条件框架下，安全目标从"检测效果"升级为"**未授权效果不可漏检**"：

$$R_{c, S, \theta}^{-}(\tau_i) = P(\tau_i(\mathbf{h}) \leq \theta_i \mid E_i \in U(c, a, S))$$

这是"发生了不应该发生的事情，但探针没检测到"的概率。

#### 结果（v2 数据，1464 条）

| 效果 | N_unauth | UnauthFNR (pooled) | [β−α]₊ | 风险 |
|------|:---:|:---:|:---:|:---:|
| network_egress | 344 | 0.333 | 0.179 | 中等 |
| file_written | 130 | 0.267 | 0.052 | 低 |
| content_fetched | 130 | 0.200 | 0.017 | 低 |

对比投影在授权条件下：（strict train-only LOTO, FPR≤0.10）FNR=0.280 vs 最佳 baseline 0.184。**对比投影弱于 supervised contrastive baseline**——这是当前 strict mitigation 方法的主要局限。

## 三、提出了什么方法

### 3.1 诊断方法：pIIA + ToolProxyGap + Auth-SafeInv

```math
ToolProxyGap_i(S_a, S_b) = [FNR_{S_b}(\tau_{S_a}^{diag}) - FNR_{S_a}(\tau_{S_a}^{diag})]_+
```

pIIA 提供因果层面的诊断证据（方向错位 vs 统计偏差），ToolProxyGap 量化安全意义的跨表面形式漏检增长。

### 3.2 缓解方法：Contrastive Projection

| 维度 | 说明 |
|------|------|
| 原理 | 低维信息瓶颈强制丢弃工具特定特征 |
| 训练 | Adam, 500 epochs, 64 batch, GPU |
| 最优维度 | 64（64-1024 消融确认） |
| 限制 | strict LOPO 弱于 best baseline；two-form effects 不可做 strict 评估 |

### 3.3 输入侧方法：Causal-Chain Conditioning（pilot）

显式因果链可以改善检测，但 wrong_chain 风险存在。作为诊断工具而非安全方法。

### 3.4 理论方法：Authorization-Conditioned Risk Accounting

$$P(\mathcal{S}(a, S) = \text{ALLOW} \mid E \in U(c, a, S)) \geq [\beta_{\text{auth}} - \alpha_{\text{auth}}]_+$$

将安全风险从"效果检测失败"升级为"未授权效果被漏放"的精确下界。

## 四、取得了什么成果

### 4.1 实证发现

| 发现 | 证据 |
|------|------|
| LLM 表征存在表面形式碎片化 | LOTO heldout FNR 0.10-0.97, pIIA-Drop 0.05-0.37 |
| 碎片化不是词汇捷径 | 词汇控制实验 FNR 基本不变 |
