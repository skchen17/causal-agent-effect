## 总体判断

这版可以支撑一篇较强的 workshop paper，也已经有冲主会的基本骨架。相比上一版，最大的进步是实验闭环更完整了：你不仅定义了工具碎片化和安全工具不变性，还展示了 LOTO 覆盖缺失下的 worst-FNR、pIIA-Drop 与 FNR-Gap 的趋势关系，以及简单 baseline 不能系统性解决问题。这个组合已经构成了清楚的 empirical safety finding。

当前最强的论文主张应是：
$$
\text{LLM 表征中的同一因果效果不一定跨工具稳定，训练覆盖缺失会导致高 FNR，而简单平衡或工具条件化方法不能可靠消除该风险。}
$$
这个主张比“提出完整因果抽象新理论”更稳，也更容易被审稿人接受。

如果目标是顶会主会，当前还差几件事：更完整的统计报告、更多 baseline、更多模型或同系列 ablation、以及对 pIIA 的因果解释进一步降调。不是方向问题，而是证据强度问题。

## 主要优点

第一，理论定义已经清楚。MultiMech 表示逻辑层事实，Frag 表示正类条件表征分布差异，ToolProxyGap 表示任务相关的经验代理指标，SafeInv 用 FNR/FPR 定义安全工具不变性。这套层级现在是自洽的。

第二，安全定理现在很稳。定理 1 使用：
$$
P(\mathcal S(a,B)=\mathrm{ALLOW}\mid E=1,T=B)\ge[\beta-\alpha]_+
$$
其中 $\beta$ 是目标工具上的 FNR，$\alpha$ 是其他安全关键效果的冗余拒绝概率。这个定理虽然简单，但不再依赖 pIIA、CTPG 或其他诊断指标，因此不会被“干预指标不等于安全失效”击穿。

第三，定理 2 的定位合理。你不再说“有限样本不可验证”，而是说自然采样下稀有工具-效果组合的覆盖成本为 $O(1/q)$。这比早期版本严谨很多，也能很好解释为什么 LOTO stress test 有意义。

第四，pIIA 的命名和作用明显改善。你明确说它是 probe-mediated，不是标准 Geiger IIA；它需要少量目标工具标注样本，不能替代 FNR；它用于诊断“方向错位”，不是直接证明安全漏洞。这些限制写出来以后，指标的可信度反而更高。

第五，baseline 部分是关键增强。现在你展示 balanced pooling 能改善部分效果，例如 `file_deleted` 从 0.60 降到 0.20、`network_egress` 从 0.73 降到 0.41，但不能系统性解决 `content_fetched`、`file_written` 等效果上的高 worst-FNR。这比单纯报告失败案例更有说服力。

## 剩余问题

### 1. 定义 7 仍有一个小但重要的口径错误

你在效果预测器处写了：
$$
\mathbf h=N(\mathrm{desc}(a,T))
$$
但在系统端到端判定最后又写：
$$
\mathbf h=N(\mathrm{desc}(a)).
$$
应统一为：
$$
\mathbf h=N(\mathrm{desc}(a,T)).
$$
这个细节必须改。工具 $T$ 是否进入输入表征是整篇论文的核心条件，不能在定义里前后不一致。

### 2. ToolProxyGap 与 FNR-Gap 基本重复，需要处理命名关系

你现在定义：
$$
\text{ToolProxyGap}_i(A,B)
=
\max(0,\mathrm{FNR}_B(\hat\tau_{i,A})-\mathrm{FNR}_A(\hat\tau_{i,A}))
$$
后面又定义：
$$
\text{FNR-Gap}_i(\mathcal L)
=
\max_{A,B}
[
R_B^-(\hat\tau_{i,A}^{diag})-R_A^-(\hat\tau_{i,A}^{diag})
]_+.
$$
这两个对象本质上是同一个量的 pairwise 版本与 max-over-pairs 版本。建议明确写：
$$
\text{FNR-Gap}_i(\mathcal L)
=
\max_{A,B}\text{ToolProxyGap}_i(A,B).
$$
否则读者会觉得定义重复。

### 3. Frag 的纯表征定义和 ToolProxyGap 的性能定义之间仍需桥接

你已经说 ToolProxyGap 是 Frag 的“任务相关代理指标”。这很合理。但它不是纯表征距离，而是包含训练算法、阈值、类别比例、正则化和样本量的结果。因此不要写成“Frag 即 ToolProxyGap”。建议使用如下表述：

“Frag 是理论上的表征分布差异；ToolProxyGap 是本文采用的安全任务相关 proxy，用于测量这种差异是否转化为跨工具漏检风险。”

这样就不会被 representation learning 审稿人质疑“分类 gap 不是分布距离”。

### 4. pIIA 判定仍然偏弱，建议补 margin 或 threshold 版本

当前 pIIA 成功条件是：
$$
\tau_i^B(h^{int})>\tau_i^B(h_L^b).
$$
这个条件只要求分数比 baseline 增加，不要求超过安全阈值，也不要求接近 source 样本。因此 pIIA-within 全部为 1.000 并不意外，但审稿人可能认为指标太容易饱和。

建议附加两个指标之一：
$$
\text{pIIA-threshold}
=
P(\tau_i^B(h^{int})>\theta_i)
$$
或
$$
\text{pIIA-margin}
=
\mathbb E[\tau_i^B(h^{int})-\tau_i^B(h_L^b)].
$$
如果 cross pIIA 的 margin 明显小，机制诊断会更可信。当前的 pIIA-Drop 可以保留，但最好不要作为唯一机制证据。

### 5. LOTO 表格仍应增加 within FNR 或 held-out source FNR

目前表格只有：

| 效果 | Max LOTO FNR | FNR-Gap |
| ---- | ------------ | ------- |
|      |              |         |

例如 `content_fetched` 的 Max LOTO FNR 是 0.781，FNR-Gap 是 0.281。这意味着对应源工具上的 FNR 约为 0.500。读者会问：为什么源工具 FNR 本身这么高？这是工具内也难，还是 held-out 工具特别难？

建议改成四列：

| 效果 | Source FNR | Held-out FNR | FNR-Gap | Held-out Tool |
| ---- | ---------- | ------------ | ------- | ------------- |
|      |            |              |         |               |

如果每个效果取 max，则写清楚最大值来自哪个 $A\to B$ 工具对。这样会显著提升实验透明度。

### 6. baseline 还不够强，tool-conditioned 结果也需要解释

你现在的 tool-conditioned baseline 在所有效果上几乎与 pooled 相同。这很奇怪，因为拼接工具 ID 理论上至少可能改变边界。可能原因包括：

1. 工具 ID 没有在 held-out 工具上可用；
2. LOTO 设置下 held-out 工具的 one-hot 维度没有训练信号；
3. 训练/测试工具条件化方式不适用于新工具；
4. 模型退化为忽略 tool id。

这些需要明确说明。否则读者会问：tool-conditioned 为什么完全不起作用？

对于主会，建议至少再补两个 baseline：
$$
\text{Group DRO / worst-group training}
$$
和
$$
\text{per-tool threshold calibration}
$$
如果时间有限，优先补 balanced pooled + group DRO。因为你的核心问题是 worst-tool FNR，group DRO 是最自然对照。

### 7. “部署探针 per-tool FNR ≈ 0”需要样本量和置信区间

这句话很强。需要报告每个工具-效果组合的正类样本数、FNR 置信区间。若某些组合正类样本很少，FNR=0 的置信区间可能很宽。

建议至少写：
$$
\hat{p}=0,\quad 95\%\ \mathrm{CI}\le \frac{3}{n}
$$
即 rule-of-three。否则“≈0”可能被认为只是样本不足。

### 8. pIIA 与 FNR-Gap 的统计关系仍偏弱

$$
\rho=0.771,\quad p=0.072,\quad n=6
$$

这是有启发性的趋势，但还不能作为强统计结论。你现在已经写 “suggestive positive trend”，很好。建议论文结构第 5.3 也改掉“统计关系”这个说法，改成：

“pIIA-Drop 与 FNR-Gap 的趋势关系”。

如果能扩展到 11 个效果，或者把 effect-tool pair 作为样本并用 clustered bootstrap 估计，会更强。

### 9. 命题 1 的经验检验还偏弱

你报告：

同家族平均 F1 = 0.57，跨家族平均 F1 = 0.42。

这支持“工具家族距离影响泛化”，但还需要置信区间和显著性检验。建议报告：
$$
\Delta=0.15,\quad 95\%\ \mathrm{CI},\quad p\text{-value}
$$
并说明 156 个工具对不是完全独立，因为它们共享工具和效果。最好用 mixed-effects regression：
$$
\mathrm{FNRGap}_{e,a,b}
\sim
\mathrm{CrossFamily}_{a,b}
+
(1|e)
+
(1|a)
+
(1|b).
$$
这会比简单均值差更有说服力。

### 10. 多模型验证仍然不足以支撑训练归因

你已经把表述降为“工具调用能力本身不保证跨工具因果方向一致”，这很稳。不要再往“函数调用训练导致/改善/恶化”上推。MiniLM 与 Qwen3-8B 差异太多，只能说明不同表示族上现象存在，不足以归因训练机制。

如果要强化这一节，最合适的是同系列：
$$
\text{base} \rightarrow \text{instruct} \rightarrow \text{tool-SFT}
$$
否则保留为“初步跨模型观察”即可。
