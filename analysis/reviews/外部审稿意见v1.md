## 2. 你这篇论文当前的创新性判断

当前创新性可以概括为：

**诊断与评估框架创新较强；方法创新中等偏弱；如果不修改定位，容易被审稿人认为方法部分与 ClawGuard / AttriGuard / ARGUS 接近。**

最有辨识度的创新点有三个。

第一，**Auth-SafeInv**。现有 benchmark 多关注 attack success rate、harmful task completion、utility/security tradeoff。你的论文关注的是 authorization-conditioned unauthorized-effect false negative rate。这是一个更细的 monitor-level safety target。

第二，**surface-form fragmentation**。你不是简单展示 agent 被攻击成功，而是指出：同一 causal effect 通过不同 tool surface form 实现时，representation-side monitor 会出现跨工具漏检。例如 content_fetched、file_written、network_egress 等 effect 在 LOTO stress test 中出现较高 held-out FNR。

第三，**effect-level authorization view**。你关心的是工具调用实际造成了什么 effect，以及该 effect 是否被任务授权。这与 AttriGuard / CausalArmor 的“为什么产生这个 tool call”、ClawGuard 的“调用前规则约束”、ARGUS 的“决策证据 provenance”不同。

但方法创新目前不够强。verifier-assisted monitoring 的形式是：

**execution trace → effect verifier → realized effects → authorization checker → ALLOW / DENY**

这个方向合理，但在已有 runtime defense 论文之后，单独作为“新方法”还不够突出。它必须被写成 **effect-verification layer**，并证明它能处理 pre-action rule enforcement / provenance auditing 容易漏掉的问题，例如 partial execution、provider-side side effects、tool alias、shell/API 等价实现、trace 与 tool name 不一致。

## 3. 建议的论文重新定位

建议不要把论文定位成：

“我们提出了一个新的 agent defense 方法。”

这个说法会被 ClawGuard、ARGUS、AttriGuard 压住。

更好的定位是：

**本文提出 authorization-conditioned effect-level safety evaluation，诊断出现有 representation-side monitors 在 tool surface-form variation 下存在高 FNR 风险，并证明 execution-level effect evidence 是实现 Auth-SafeInv 的必要组成。**

也就是说，主贡献排序建议改成：

1. **Auth-SafeInv：新的授权条件安全评估目标**
2. **Surface-form fragmentation：新的安全监控失败模式**
3. **pIIA / ToolProxyGap：诊断该失败模式的工具**
4. **Verifier-assisted authorization monitoring：实现 Auth-SafeInv 的框架性方法**
5. **Contrastive projection：observed-pair upper-bound，不作为主方法**

这样写，创新性更稳。

## 4. 最重要的修改建议

### 修改 1：把相关工作写成“差异矩阵”

你需要在 Related Work 或 Discussion 中加一个表，明确区分这些工作：

| 工作类型                       | 代表论文                    | 判断对象            | 主要信号                             | 你的论文差异                                       |
| -------------------------- | ----------------------- | --------------- | -------------------------------- | -------------------------------------------- |
| prompt injection benchmark | AgentDojo, ASB          | agent 是否被攻击成功   | attack success / utility         | 你的目标是 unauthorized effect FNR                |
| risk discovery benchmark   | ToolEmu                 | agent 风险失败      | LM-emulated tool outcome         | 你的目标是 effect-level monitor invariance        |
| harmful task benchmark     | AgentHarm               | 是否完成恶意任务        | harmful task completion          | 你的目标是 task-authorized effect consistency     |
| causal attribution defense | AttriGuard, CausalArmor | tool call 为什么产生 | counterfactual replay / ablation | 你的目标是 tool call 实际造成什么 effect                |
| boundary enforcement       | ClawGuard               | 调用前是否符合规则       | user-derived constraints         | 你的方法关注 execution evidence 与 realized effects |
| provenance auditing        | ARGUS                   | 决策是否由可信证据支持     | influence graph                  | 你的方法关注 effect 是否发生与是否越权                      |

这个表会直接降低审稿人对 novelty 的质疑。

### 修改 2：把 verifier-assisted monitoring 做成明确方法，而不是实验现象

当前论文里 verifier-assisted monitoring 有强结果，但写法更像“我们发现 execution verifier 很有效”。建议改成明确方法：

**EffectVerif-AuthMonitor**

输入：task context c、authorized envelope A(c)、tool call a、surface form S、arguments、execution trace t。
模块 1：Effect Verifier，从 trace t 中抽取 realized effect set Ω̂(a,S,t)。
模块 2：Authorization Checker，计算 Û(c,a,S,t)=Ω̂(a,S,t)\A(c)。
输出：若 Û 非空则 DENY，否则 ALLOW。

然后给出伪代码、接口定义、trace schema、effect taxonomy、failure modes。

这一步很关键。没有这个结构，方法部分会显得像自然工程组合；有了这个结构，论文才有可复现方法形态。

### 修改 3：证明你的方法不是 ClawGuard / ARGUS / AttriGuard 的重复

建议新增一组对比实验或至少 conceptual ablation：

**Pre-action rule-only baseline**：模拟 ClawGuard 类方法，只看 user objective、tool name、arguments、policy rule，不看 execution trace。
**Provenance-only baseline**：模拟 ARGUS 类方法，只判断 tool call 是否由可信上下文支持，不判断实际执行 effect。
**Action-attribution baseline**：模拟 AttriGuard 类方法，只做 counterfactual tool-call survival，不做 effect verification。
**Your method**：看 execution trace，抽取 realized effects，再做 authorization check。

测试样例要包含这些情况：

工具名看似安全，但实际 trace 发生 network egress；
tool call reason 合法，但执行产生额外副作用；
shell command 与 API tool 表面不同，但 effect 相同；
provider API 返回成功，但本地 static rule 看不出真实远端 effect；
命令部分失败但产生 partial side effect。

这些样例能证明你的方法补的是“effect realization gap”，而不是重复已有 runtime guard。

### 修改 4：补强 verifier 独立性

这是最影响有效性的实验。你必须证明 verifier 不是从 trace 中读到了显式标签。

建议做三版 trace：

**Full trace**：保留完整字段。
**Label-hidden trace**：去掉 effect_name、event_type、policy_decision 等近似标签字段。
**Minimal evidence trace**：只保留 file diff、HTTP request/response、exit code、stdout/stderr、API status、message receipt 等低层证据。

然后报告 FNR/FPR。若 minimal evidence trace 仍显著强于 static verifier，方法可信度会大幅提升。

### 修改 5：从 candidate-effect row 指标升级到 action-level 指标

现在很多结果是 per-effect candidate row 的 FNR/FPR。真实 monitor 最终要判断一次 tool call 是否 ALLOW / DENY。

建议主表改为 action-level：

Unauthorized Action Allow Rate，越低越好；
Authorized Action False Denial Rate，越低越好；
Macro unauthorized-effect FNR；
Macro authorized/absent-effect FPR；
Per-effect breakdown；
Per-tool-family breakdown。

这样更贴近 AgentDojo、ASB、ClawGuard、ARGUS 的评价习惯，也更容易和相关工作对话。

### 修改 6：把 contrastive projection 降级

不要把 contrastive projection 作为主方法。论文已经显示，在 strict Auth-SafeInv splits 下，pure representation-side 方法不如较强 baseline；它更适合作为 upper-bound evidence：当模型见过 cross-form positive pairs 时，表示对齐可以修复一部分 fragmentation，但它不解决授权条件下的真实泛化问题。

建议写法：

“Contrastive projection demonstrates that observed surface-form pairs can be partially aligned, but strict authorization-conditioned generalization remains unsolved by representation-only repair.”

这样反而能增强主论点：需要 execution-level effect evidence。

## 5. 修改后的贡献声明建议

可以把贡献声明改成下面这种结构：

1. **We formulate authorization-conditioned causal task consistency** for tool-augmented agents, where safety depends on whether realized effects are contained in the task-authorized envelope.

2. **We introduce Auth-SafeInv**, an evaluation target focusing on unauthorized-effect false negatives and authorized/absent-effect false positives under surface-form variation.

3. **We identify surface-form fragmentation** as a representation-level failure mode: effect probes that work on covered tools can miss the same realized effect on held-out tool surfaces.

4. **We provide diagnostic tools**, including ToolProxyGap and pIIA, to measure cross-surface effect transfer failure.

5. **We propose verifier-assisted authorization monitoring**, which separates realized-effect verification from authorization checking, and show that execution-level effect evidence substantially reduces unauthorized-effect misses in controlled/API/local-adapter trace settings.

这个贡献声明比“我们提出新方法解决 agent safety”更稳。

## 6. 最终判断

这篇论文如果按“方法论文”投稿，目前创新性不够强，容易被认为和 ClawGuard、ARGUS、AttriGuard 等 runtime defense / causal attribution 工作接近。

如果按“评估框架 + 失败模式诊断 + verifier-assisted framework”投稿，创新性是够的。它和主会 benchmark 工作的差异在于：主会工作多评估 agent 是否被攻击或是否完成有害任务；你的论文评估 **安全监控器是否能识别实际 effect 并判断其是否被授权**。这个角度有明确新意。

最重要的修改方向是：

**把论文主轴从“提出一个防御方法”调整为“提出 Auth-SafeInv 评估目标，诊断 representation monitor 的 surface-form fragmentation，并证明 execution-level effect verification 是必要方法层”。**

这样修改后，论文的创新性会更清楚，和最新相关工作的边界也更稳。
